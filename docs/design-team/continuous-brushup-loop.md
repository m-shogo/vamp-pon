# Continuous Brush-up Loop

Vamp Pon visual work must improve through repeated loops, not one-time fixes.

## Core idea

Do not ask for one perfect asset once.
Ask for repeated improvement with evidence.

```txt
brief -> A/B/C prototype -> review -> merge best parts -> v2 -> review -> v3 -> promotion check
```

## Loop stages

| Stage | Goal | Output |
| --- | --- | --- |
| Brief | define role and target | intended asset role, matching design role, target score |
| A/B/C | explore directions | three small prototypes or three written visual plans |
| Review | find why it is 60/70 | design-team review doc |
| Merge | choose best parts | keep/discard list |
| v2 | focused improvement | improved prototype |
| v3 | hand-finish direction | Aseprite-ready correction list |
| Gate | production decision | 80+ score and evidence |

## Required every loop

- current score
- target score
- what still looks generic
- what should stay
- what should be discarded
- next exact edit
- final decision: reject / remake / iterate / production-candidate

## Stop conditions

Stop and ask for a human decision when:

- two iterations do not improve the score
- the asset still looks like another existing asset
- 1x readability and 4x charm conflict
- the design role is unclear
- production promotion would require gameplay changes

## Do not

- Do not call one pass complete.
- Do not accept self-scored 80 without evidence.
- Do not continue polishing a weak concept forever.
- Do not move to production without source and review proof.
