# Quality Examples

This page explains the difference between weak prototype quality and target app quality.

## Prototype quality

- readable but generic
- silhouette is not memorable
- focal point is weak
- color plan is safe but not intentional
- UI is themed but hard to scan
- background has too much equal detail

## Target app quality

- readable at 1x
- recognizable silhouette
- clear focal point
- useful color contrast
- one memorable idea
- fits the Vamp Pon world
- still looks good at 4x review

## Asset checks

| Asset | Weak sign | Target sign |
| --- | --- | --- |
| avatar | only hair or color differs | three identifiers and readable face |
| monster | shape family is unclear | unique family silhouette and movement cue |
| item | generic symbol | function and story are both visible |
| background | detail everywhere | quiet gameplay center |
| UI card | decoration first | title and icon first |
| icon | meaning needs text | meaning is readable quickly |

## Rule

If the reason for target quality cannot be explained, keep the asset as prototype.
