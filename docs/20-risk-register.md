# リスク台帳: 既存モチーフ・世界観・表現

## 目的

Vamp Pon は、0から世界観を作るのではなく、昔話・童話・動物・民話など既存モチーフを参考にする可能性がある。

ただし、既存モチーフを使う場合は以下のリスクがある。

- 著作権
- 商標
- キャラクター権利
- 特定作品のデザイン模倣
- 動物愛護・暴力表現
- 文化表現・ステレオタイプ
- 配信プラットフォーム審査
- AI生成素材の権利不明瞭さ

このドキュメントは、肯定だけで進めず、将来の販売・公開まで考えてリスクを整理するためのもの。

## 最重要方針

既存モチーフは使ってよいが、**特定作品の絵・名前・ロゴ・デザイン・固有演出をコピーしない**。

安全寄りの使い方:

```txt
民話/童話の構造を参考にする
一般的なモチーフを使う
自分たちの名前・見た目・設定に変える
複数モチーフを混ぜる
特定企業版のビジュアルから離す
```

危険な使い方:

```txt
ディズニー版アリスっぽい服・色・構図にする
既存ゲームのUIや武器名を似せる
商標名をタイトルや売り文句に使う
既存キャラそのものを出す
AIに特定作品風を強く指定して素材化する
```

## リスク一覧

| リスク | 危険度 | 内容 | 対策 |
|---|---:|---|---|
| 著作権 | 高 | 既存の絵、文章、キャラデザイン、音楽、UIをコピーすると危険 | 原典モチーフだけ使い、表現は独自化 |
| 商標 | 高 | タイトル、キャラ名、商品名が既存ブランドと混同される可能性 | 固有名詞を避け、独自タイトル/名称にする |
| デザイン模倣 | 高 | パブリックドメイン原作でも、有名映画版やゲーム版の見た目は別権利 | 色、服、形、ロゴ、構図をずらす |
| AI生成素材 | 中〜高 | プロンプト次第で既存作に似る可能性 | 特定作家名/作品名/企業名を避ける。人間が修正する |
| 動物愛護 | 中 | 動物を攻撃対象にすると不快感が出る可能性 | 敵は影、ぬいぐるみ、魔物、いたずら精霊などにする |
| 暴力表現 | 中 | かわいい動物を大量に倒すと印象が悪い | 消える、浄化、眠る、元に戻る表現にする |
| 文化表現 | 中 | 桃太郎、鬼、妖怪などを雑に扱うとステレオタイプ化する | リスペクトある抽象化。現実の民族/宗教を敵化しない |
| 子ども向け誤認 | 中 | 見た目が幼いのに課金・中毒性が強いと印象が悪い | 課金なし、ログイン圧なし、やさしい表現 |
| プラットフォーム審査 | 中 | Steam等で権利侵害素材や不適切表現が問題化する可能性 | 素材出所を記録し、権利表を作る |

## 著作権リスク

### パブリックドメインでも安全とは限らない

昔話や古い童話の物語そのものは使いやすいことが多い。

ただし、以下は別。

- 近年の映画版デザイン
- 有名アニメ版の衣装や配色
- 近年の挿絵
- 翻訳文
- 編曲BGM
- ロゴ
- キャッチコピー

例:

アリスの原作は古いが、ディズニー版の青い服・白エプロン・特定の顔立ち・世界観に寄せると危険。

### 安全寄りルール

- 原作名をそのままタイトルに使わない
- キャラ名をそのまま主役名にしない
- 見た目を有名版から離す
- 複数モチーフを混ぜる
- 自分たちの世界設定を作る
- 出典メモを残す

## 商標リスク

商標は、著作権とは別。

古い物語名でも、ゲームタイトルや商品名として使うと、既存商標との混同リスクがある。

避けること:

- `Alice Survivor` のような直球タイトル
- `Wonderland` を強く売りにする
- 既存ゲーム/映画/ブランド名に近い武器名
- ロゴやフォントを有名作に寄せる

安全寄り:

- 完全に独自タイトル
- モチーフは説明文や中身で匂わせる
- キャラ名・武器名をオリジナル化

## 動物愛護・動物表現リスク

動物モチーフはかわいいが、扱いを間違えると不快感が出る。

### 危険な方向

- かわいい実在動物を大量に倒す
- 犬、猫、うさぎを敵として攻撃する
- 血や痛みを強調する
- 動物虐待に見える演出
- ペットを武器化する

### 安全な方向

- 敵は影、魔物、ぬいぐるみ、紙人形、いたずら精霊にする
- 倒すではなく、浄化・眠らせる・元に戻す表現にする
- 味方動物は傷つけない
- 動物は仲間やサポート役にする
- 敵動物にする場合は現実動物から離したデフォルメにする

## 文化表現リスク

桃太郎、鬼、妖怪、昔話を使う場合は、雑に敵味方へ割り振ると浅く見える。

### 注意点

- 鬼をただの悪者にしすぎると古い記号に頼りすぎる
- 民話を混ぜすぎると意味がなくなる
- 和風記号だけ並べると薄くなる
- 宗教的・民族的モチーフを雑に敵化しない

### 安全な方向

- 「昔話そのもの」ではなく「昔話の道具・構造」を使う
- 鬼は敵だけでなく、ボス/商人/仲間にもできる
- 桃太郎をそのまま出さず、桃・団子・旅・仲間の構造だけ使う
- 妖怪はかわいい怪異として扱う

## AI生成素材リスク

AIで背景・キャラを作る場合、プロンプトが危険になることがある。

避けるプロンプト:

```txt
ディズニー風アリス
ジブリ風桃太郎
任天堂風どうぶつ
〇〇先生風イラスト
有名ゲームのUI風
```

安全寄りプロンプト:

```txt
public-domain fairy tale inspired, original character design
storybook toy-box night, original cute spooky creatures
Japanese folktale inspired, original stylized props, no existing character likeness
```

ただし、AI生成物はそのまま商用利用前提にせず、人間が選別・修正・権利メモを残す。

## プラットフォーム公開リスク

将来的にSteam、itch.io、App Store等へ出す場合、素材の出所が重要になる。

必要になるもの:

- 素材台帳
- ライセンス一覧
- 使用フォントのライセンス
- BGM/SEのライセンス
- AI生成素材のプロンプト記録
- 参考作品と採用表現の差分メモ

## モチーフ別リスク評価

| モチーフ | 使いやすさ | 主なリスク | 方針 |
|---|---:|---|---|
| 動物 | 高 | 動物虐待に見える表現 | 味方/サポート中心、敵は影や魔物化 |
| 日本昔話 | 中〜高 | 文化記号の浅さ、桃太郎そのまま感 | 構造と小物を使う。固有名は避ける |
| アリス系 | 中 | ディズニー版連想、商標/デザイン混同 | 原作一般モチーフだけ。青服白エプロン回避 |
| グリム童話 | 中 | 残酷表現、既存映画版連想 | 童話構造を柔らかく再解釈 |
| おもちゃ箱 | 高 | 既存IPに寄せなければ比較的安全 | オリジナル化しやすい。本命候補 |
| 妖怪 | 中 | 文化表現、既存妖怪作品との差別化 | かわいい怪異として独自デザイン |

## 推奨方針

一番安全で広げやすいのは、以下。

```txt
主軸: おもちゃ箱/夜/動物
補助: 昔話・童話の道具や構造
避ける: 特定作品そのもの
```

つまり、桃太郎やアリスをそのまま出すのではなく、以下のように分解して使う。

### 桃太郎から借りるもの

- 桃
- 旅
- 仲間
- 団子
- 鬼ヶ島的な遠い場所
- 宝物

### アリスから借りるもの

- 鍵
- 時計
- 不思議な庭
- お茶会
- カード
- 迷路
- サイズ変化

### 動物から借りるもの

- 仲間
- サポート
- 武器モチーフ
- 図鑑
- かわいい収集要素

## 採用前チェックリスト

新しい世界観・敵・武器・報酬を採用する前に確認する。

- 特定作品のキャラそのものではないか
- 有名版の色や服に寄りすぎていないか
- 名前が既存商標や有名タイトルに近すぎないか
- 実在動物を痛めつける印象にならないか
- 文化や民話を雑に消費していないか
- AI生成素材の出所を記録できるか
- 素材ライセンスを説明できるか
- 将来販売しても説明できるか

## 現時点の結論

0から作らない方針は正しい。

ただし、既存作品そのものを使うのではなく、**パブリックドメイン的な昔話・童話・動物モチーフを分解し、Vamp Pon独自の世界に再構成する**。

最も安全寄りの本命:

```txt
おもちゃ箱の夜 × 動物の仲間 × 昔話/童話の道具
```

ここなら、背景・敵・武器・報酬を広げやすく、著作権・動物表現・文化表現のリスクも比較的制御しやすい。
