# Stage1 演出・描画実装方針

## 結論

Stage1のゲームプレイにはThree.jsを追加しない。

現在のruntimeはPhaser 4.1.0で統一されている。Stage1ではPhaser/WebGLの範囲で、紙・インク・灯り・朝の演出を積み上げる。

Three.jsは将来、タイトル画面や図鑑の紙ジオラマなど、ゲームプレイと別canvasに分離できる用途だけ再検討する。

---

## Three.jsを今入れない理由

- PhaserとThree.jsの2つのrendererを同時管理する必要がある
- WebGL context、camera、resize、pointer座標の同期が増える
- スマホでbundleとGPU負荷が増える
- 2Dドット絵のゲーム中演出に3D rendererは過剰
- 不具合時にゲームロジックと描画問題の切り分けが難しくなる

Three.jsを使わないことは演出を弱くする判断ではない。
Stage1では、2D画面に合ったscreen-space演出、particle、camera、post effectを丁寧に組む方が品質と速度の両方で有利。

---

# 演出の基本原則

1. プレイヤー・敵・欠片を見失わせない
2. 発光を常時重ねず、重要な瞬間だけ使う
3. 大量敵時にも60fpsを優先する
4. 紙・インク・灯り・記憶という世界観の形で差別化する
5. 画面全体を揺らす演出は短くする
6. 強い演出後は必ず静かな時間を作る
7. エフェクトだけで攻撃範囲を誤認させない

---

# 実装レイヤー

## Layer 1: Gameplay readability

最優先。

- chargerの予兆線
- orbit敵の進路表示
- eliteの出現警告
- プレイヤー被弾フラッシュ
- 回復ドロップの非磁力表示
- カプセル敵の報酬感
- 実攻撃範囲と見た目の一致

## Layer 2: Hit satisfaction

- 敵撃破時の黒インク飛沫
- 複数撃破時の小さい連鎖光
- 武器別の着弾形状
- 強敵撃破時だけ少し強いcamera shake
- 暴走中の攻撃へ短い黒残像

## Layer 3: Build growth

- 新規武器取得時の紙片展開
- Lvアップ時の短い縁光
- 強化進化: 紙片が上へ広がる
- 合体: 黒インクと灯りが中央で重なる
- 覚醒: 記憶札が立ち上がる
- 進化後武器は通常版と残像・色温度・形を変える

## Layer 4: Run pacing

- 150秒elite前の警告
- elite撃破後の短い静寂
- 300秒で背景色温度を少し変える
- 420秒で最終区間の圧を予告
- ラスト10秒のvignette・拍動
- 480秒で敵更新停止、朝色wash、clear表示

## Layer 5: Character states

### 通常必殺

- 暖色flash
- ユイ通常必殺カットイン
- ランタン光の円
- 紙片が外へ流れる

### 暴走

- ユイ暴走カットイン
- 黒炎
- portraitの黒紋章
- 攻撃残像
- 軽い色収差ではなく、黒い輪郭揺れ
- 終了後は低彩度・短い呼吸時間

暴走は必殺と別演出・別ゲージ・別色にする。

# 品質段階

## Low

- fullscreen overlay最大1枚
- particle数を半減
- 残像なし
- vignette静止
- camera shake最小

## Standard

- 通常のparticle数
- 短い残像
- vignetteの弱い変化
- 進化モチーフ演出

## High

- particle数増加
- 短いtrail
- 背景の弱い色温度変化
- elite撃破時の追加紙片

Stage1初期公開はStandardを既定にする。
端末性能による自動切替はPWA直前に追加する。

---

# パフォーマンス予算

- 基準: 390 x 844で60fps
- 最大敵数: 140
- 最大projectile数: 140
- fullscreen半透明overlay: 同時1〜2枚まで
- 1回の通常撃破で生成する一時object: 3個以下
- elite/進化のみ10〜20個まで許可
- 毎frame新しい配列・文字列を大量生成しない
- particle textureは再利用する
- 画面外effectは生成しない
- tween終了時に必ずdestroyする

# Three.jsを採用してよい条件

次をすべて満たす場合のみ検討する。

- Stage1が8分完走可能
- スマホ実機で安定60fps
- Phaser側の演出が完成
- 3Dを使う画面がゲームプレイと分離されている
- Three.jsなしでは表現できない明確な目的がある
- bundle増加とメモリ増加を計測できる

候補用途:

- タイトル背景の紙の街ジオラマ
- 図鑑のページをめくる3D演出
- ステージ選択の小さな立体地図

ゲーム中の弾、敵、背景、暴走、進化には使わない。
