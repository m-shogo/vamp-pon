# 2. Why three colors

## Primary

Use for:

- Character DB stripe
- relationship graph node accent
- profile heading marker
- small UI underline
- Character Book tab

Do not flood full screen with Primary.

## Accent

Use for:

- lighter supporting details
- secondary line / chip background
- printed Character Book ornaments
- clothing prop Candidate research marker

## Night Glow

Use for:

- Dream UI subtle glow
- lantern/particle hint
- relationship node hover
- rare cut-in accent

Night Glow is **not automatically magic aura**.

# 3. Family / relation color policy

User direction:

> 親族や兄弟なら被っても意味あるように。それ以外は意味なく被らせない。

Working interpretation:

### Fixed sibling example — Ritsu / Koyori

Use same **rose hue family**, not exact same HEX.

- Ritsu: deeper `#B9475A`
- Koyori: lighter `#ED8FA1`

Meaning:
- shared household history
- different age / autonomy

Not:
- Koyori is “small Ritsu”.

### Twin example — Kai / Nao

Use same **cool-sky family**, not mirror-identical palette.

- Kai: `#4B86C2`
- Nao: `#7387D4`

They may occasionally share Accent family in paired art, but standalone identification must survive color-blind and grayscale conditions.

### Nagi → Yui parent Candidate

Do **not** share the same hue as a clue right now.

Reason:
> Parent Candidate is not Canon. Theme color must not become accidental lineage evidence.

### Tomori → Touma ancestor Candidate

Likewise no deliberate same-hue blood clue.
Tomori brown/wood and Touma patina teal are intentionally different.

Object inheritance and craft echoes can connect them without color proof.

# 5. Color should not recolor bodies

Never derive:

- skin tone
- hair color
- eye color
- tattoo color
- disability equipment color
- animal fur
- Robot material

from theme color automatically.

Example:

- Hiyori Primary yellow does not mean warmer/darker skin edit.
- Touma teal does not mean skin undertone edit.
- Suzu magenta does not require pink hair/clothes.
- Amane teal does not require teal wheelchair.
- Rum mint does not require mint chassis.
- Kuu ochre does not change dog coat.

# 6. Accessibility

Color is supplemental.

Every UI use must have at least one non-color identifier:

- name
- portrait
- icon
- shape
- pattern
- line style
- label

Relationship graph:

Bad:
> red = family, blue = friend, green = enemy only.

Better:
- color + line shape + label/icon

Theme color should survive:

- grayscale
- low brightness
- dark mode
- common color-vision deficiencies

Exact WCAG/background pairing is separate UI implementation review because these HEX values are identity accents, not guaranteed text/background pairs.

# 7. Dark-mode / Dream UI usage

Recommended hierarchy Candidate:

```txt
black ink / night background
↓
paper / lantern neutral
↓
Character Primary 5–15% area
↓
Night Glow only at focus / rare feedback
```

Avoid:

- 36 neon cards
- RGB gamer glow
- full-screen faction color wash
- every Character outline glowing constantly

The game visual rule remains:

> 通常画面は静か、rare演出だけ派手。

# 9. Relationship graph strategy

Potential visual system:

### Person node
Character Primary.

### Relation edge
Relation category has its own shape/pattern, not another character color.

### Shared family hue
Only when relation is Current/Canon enough to justify it.

### Candidate lineage
No color hint unless Human Review intentionally wants foreshadowing.

### Former enemy
Do not recolor Character to ally/enemy faction color after alignment change.
Character color follows person, not current team.

This is especially important for Sakuyaza individual returns.

# 10. S1 / S2 enemy policy

Character theme color is independent from antagonist team branding.

Good:
- Sakuyaza member keeps personal color if later ally.
- S2 Candidate color is personal, not 衡守会 uniform color.

Bad:
- all enemies red
- all allies blue
- character palette changes on redemption

Team visual motifs should be layered separately.

---

# 11. Generated art guard

When generating Character art:

Theme color can be prompt guidance such as:

> subtle accent / small prop / reflected light / UI framing

Do not prompt:

> entire outfit, hair, eyes, background and aura all in #XXXXXX

Generated art may introduce a better color relationship.
If so:

1. keep generated result as Candidate
2. compare against 36-color collision
3. check Physical Identity
4. check family/lineage spoiler implications
5. update Reservoir later

Generated visual accident never becomes Canon.
