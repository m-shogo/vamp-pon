# Vamp Pon Stage 1〜5 One-Shot Visual Generation Brief

## 0. この文書の位置づけ

この文書は、Vamp Pon の Stage 1〜5を、ChatGPT系の画像生成・設計支援へ一括で渡すためのマスター指示書である。

`docs/148-stage1-visual-generation-brief.md` は Stage 1単体の詳細資料として残すが、初回のビジュアル設計・方向性決定では本書を優先する。

理由:

- Stageごとの色、密度、縮尺、ランドマークの強さを横並びで整えるため
- 5面の進行感を一度に確認するため
- Stage 1だけ過剰に作り込まれ、Stage 2〜5が後付けになるのを防ぐため
- スマホ・タブレット・PC・将来のアプリ表示を同じ設計思想で揃えるため

ただし、一括生成は「5面をそのままproductionへ入れる」ことではない。

```txt
5面一括コンセプト
→ 横並びレビュー
→ 共通ルール修正
→ 5面一括再調整
→ 素材分解
→ preview実装
→ 実プレイ確認
→ production候補
```

---

# 1. 一括生成の目的

Stage 1〜5を単独作品ではなく、同じ絵本・地図帳に綴じられた5枚のページとして成立させる。

## 共通するもの

- 絵柄
- ドット密度
- 紙の厚み
- 黒インクfamily
- 夜の空気
- 中央の戦闘視認性
- UI reserve
- 390×844の論理画面
- overscan
- browser / app shell

## Stageごとに変えるもの

- 象徴物
- 地面の大きな形
- ランドマーク
- 動線
- 光の意味
- 主色
- 感情
- 場所の記憶

## 5面を通した変化

```txt
Stage 1  拾う
Stage 2  呼ぶ／近づく
Stage 3  守る／開ける
Stage 4  帰る方向を読む
Stage 5  灯りをつなぐ
```

色と構図も、静かな夜から朝の兆しへ進行させる。

# 2. 一括出力で必ず作るもの

## Output A: Five-Stage Environment Lineup

Stage 1〜5の環境コンセプトを、同一画像内または同一回答内で横並び比較できる形で作る。

各Stageは次を揃える。

- 同じ視点
- 同じドット密度
- 同じ画面縮尺
- 同じプレイヤー想定サイズ
- 同じ中央戦闘床比率
- 同じUI reserve
- 同じoverscan方針

背景のみ。UI、キャラ、敵、弾は描かない。

## Output B: Five-Stage Gameplay Composite Lineup

Output Aで承認された構図を変えず、5面すべてにゲーム要素を載せる。

各Stageに配置:

- ユイ
- 共通小型シャドウ
- 共通中型シャドウ
- Stage固有敵
- 弾
- 記憶の欠片またはStage固有ドロップ
- 上部HUD
- 左下スティック
- 右下必殺ボタン

5面を横並びにし、どの面でも同じゲームに見えることを確認する。

## Output C: Device Consistency Board

同じ5面の設計を以下で確認する。

- 390×844スマホ縦
- 縦長スマホ
- タブレット縦
- PC 16:9
- PC 21:9

PCでは中央コアゲームを維持し、左右shellだけをStageごとに展開する。

## Output D: Cross-Stage Design Matrix

画像生成だけで終わらせず、以下を表で出す。

- Stage名
- 象徴物
- 主色
- 補助色
- 光色
- 地面シルエット
- 主ランドマーク
- 動線
- 中央の静けさ
- 外周密度
- 他Stageとの差
- 共通素材
- 固有素材

# 3. 全Stage共通の絶対ルール

## 3.1 画面

```txt
logical core: 390×844
composition master: 720×1280以上
orientation: portrait
```

コア画面ぴったりで構図を切らず、上下左右にoverscanを持つ。

## 3.2 中央戦闘床

各Stageで画面面積の55〜65%を静かな戦闘床にする。

中央へ置かない:

- 大型ランドマーク
- 読ませる文字
- 強い発光
- 大型障害物
- 強い輪郭の床模様
- 敵の予告線と競合する線

## 3.3 UI reserve

```txt
上部: HUD reserve
下部: 操作UI reserve
左右端: spawn警告・可変crop reserve
```

重要物をUI reserveへ置かない。

## 3.4 絵柄

- 柔らかい高品質ピクセルアート
- 絵本の丸く少し歪んだ形
- 大きな色面
- 手描き感のある不均一な線
- 紙の厚みを1〜2px程度の縁で見せる
- 可愛いが幼児向けにしない
- 暗いがホラーへ寄せない
- シルエット優先

## 3.5 視認性順位

```txt
危険予告
プレイヤー
敵
攻撃
重要ドロップ
記憶の欠片
ギミック
背景ランドマーク
小物
床質感
```

## 3.6 背景密度

目安:

- 静かな戦闘床: 55〜65%
- 軽い装飾: 20〜25%
- 強いランドマーク: 10〜15%
- 強い演出: 最大5%

## 3.7 禁止

- 5面を色違いだけで作る
- 各Stageで絵柄や解像感を変える
- Stage 1だけ密度を高くする
- リアルな石畳
- 中世RPG村
- ホラー墓地
- 全面ディザ
- 写真紙テクスチャ
- 等間隔の装飾
- 読める文章
- ロゴ
- Stage名を背景へ直接描く
- 画面中央を装飾で埋める
- 5面すべてに同じランドマーク配置

# 4. 共通世界の見せ方

5面は別世界ではなく、同じ巨大な地図帳・絵本の異なるページ。

全Stageで薄く維持する共通記号:

- ページの層
- 黒インクのページ間
- 手描きの地図線
- 丸く少し歪んだ紙オブジェクト
- 古紙の縁
- 小さな光
- 夜から朝へ向かう空気

ただし共通記号を毎面同じ場所へ置かない。

## 黒インク

黒インクは単なる汚れではない。

- 意味を固定するもの
- ページ間に溜まる
- 敵のfamilyとつながる
- Stageが進むほど光との関係が変わる

## 光

```txt
Stage 1: 拾う対象
Stage 2: 書き直された痕跡
Stage 3: 守られた内側
Stage 4: 帰り印
Stage 5: 接続そのもの
```

- 青紫黒

最も静かで広い。

- 大きな薄い色むら

### 他Stageとの差

明暗の領域分けが最も明確。過去4面の要素を主役化せず、反応だけ見せる。

# 6. 5面の色進行

## 基本

| Stage | 主色 | 光の意味 | 明るさ |
|---:|---|---|---|
| 1 | 青灰 | 拾う欠片 | 静かな中暗度 |
| 2 | 葡萄紫 | 書き直し跡 | 白い空白が増える |
| 3 | 焦茶紫 | 守られた内側 | 暖色が局所化 |
| 4 | 青緑黒 | 帰り印 | 線状の光 |
| 5 | 深藍黒 | 接続 | 琥珀から朝色へ |

## 統一

- 黒インクfamilyは5面共通
- 古紙の縁色は共通
- 光の彩度上限を揃える
- Stage 5だけ白飛びさせない
- Stage 1と4を同じ青系に見せない

# 7. スマホ・ブラウザ・アプリ共通ルール

## スマホ

- 390×844を基準
- ノッチ・ホームインジケータを画像へ焼き込まない
- HUDと操作UI背後を静かにする
- 親指で隠れる下部へ象徴物を置かない

## タブレット

- コアゲーム範囲は変えない
- 左右に遠景・外周だけを追加
- 敵や欠片を余剰領域へ出さない

## PC

```txt
left shell | core gameplay | right shell
```

- shellはStage固有の外周延長
- ゲーム面より暗い
- 強いアニメーションなし
- 黒帯に見せない
- 鏡像コピー禁止

## アプリ

- portrait lockを本命とする
- OS safe areaはruntimeで処理
- バックグラウンド移行時はポーズ
- 復帰直後に即被弾させない
- 画像へ端末固有UIを描かない

# 8. 一括生成用マスタープロンプト

以下を一つの指示として使用する。

```txt
あなたはゲームのアートディレクター兼レベルデザイナーです。
スマホ向け縦画面サバイバーライクゲーム「Vamp Pon」のStage 1〜5を、一括したビジュアルシリーズとして設計・制作してください。

最重要条件:
5ステージを別々に考えず、同じ巨大な絵本・地図帳に綴じられた5枚のページとして、一度に整合性を取ってください。絵柄、ドット密度、画面縮尺、紙の厚み、黒インクfamily、プレイヤー想定サイズ、中央の戦闘床比率、UI安全領域を全Stageで統一してください。

出力はまず、背景のみの5ステージ環境コンセプトを横並び比較できる形にしてください。各Stageは縦長720×1280以上の構図マスターを想定し、中央390×844へ切り出しても成立し、タブレットとPCでは周囲の背景を追加表示できるoverscanを持たせてください。

共通の絵柄:
柔らかい高品質ピクセルアート。絵本の丸く少し歪んだ形をドットへ翻訳し、大きな色面、読みやすいシルエット、手描き感のある不均一な線、少ないピクセルで表した紙の厚みを使う。可愛いが幼児向けではなく、暗いがホラーではない。背景単体の美麗イラストではなく、多数の敵、弾、ドロップ、UIが重なるゲーム画面を支える環境にする。

全Stage共通:
画面面積の55〜65%を静かな中央戦闘床にする。中央に大型ランドマーク、強い発光、読める文字、強い床模様、通行を塞ぐ大型障害物を置かない。世界観は主に中景と外周で見せる。上部HUD、下部操作UI、左右端の警告領域を空ける。特定作品の画面や配色を直接模倣しない。

Stage 1「ちぎれた夜の広場」:
忘れられた小さな街の広場が、巨大な地図帳の一ページとして残っている。主色は青灰色の古紙、青紫黒、くすんだ古紙金。中央は5面中もっとも静か。中景に名前が消えたポスト、インクに少し沈んだベンチ、低い紙草、消えかけた道。外周に丸い紙の家、折れた鉛筆街灯、めくれたページ端、下層の紙。主ランドマークは折れた大きな鉛筆街灯。象徴は記憶の欠片であり、街灯を主役にしすぎない。

Stage 2「名前をなくした札庭」:
名札、ラベル、呼び名が植物や道標のように育つ紙の庭。主色は葡萄紫、薄い藤色、白紙色、黒紫。中景に糸で吊られた名札、書き直し跡、空白の小札、紙の低木。外周に名札の木、空白の掲示板、名前が切り取られた門。主ランドマークは巨大な空白名札か名札の木のどちらか一つ。墓地には見せない。Stage 1より少し分節するが、中央戦闘床は維持する。

Stage 3「月箱の保管庫」:
理由が壊れないよう、紙箱が積まれた夜の保管庫。主色は焦茶紫、くすんだ封蝋赤、月白、暗い朱。準中央に大きな月箱を置いてよいが、戦闘床を完全に塞がない。中景に紐、封蝋、小箱、内向きの鍵穴記号、月の印。外周に箱山、紙棚、閉じた紙扉、厚紙の壁面。主ランドマークは月箱。近づくか離れるかを視覚的に判断できる構図。迷路にはしない。

Stage 4「逆さ改札と帰り線」:
切符、線路、地図、改札が混ざった夢の帰路。主色は青緑黒、褪せた水色、切符裏面の橙、冷たい白。中央を複数の大きな帰り線が横切るが、細線を増やしすぎない。中景に切符床、逆向き矢印、パンチ穴、消えた路線図。外周に紙の改札、行き先のない標識、暗闇へ続く線路、ページ端のホーム。主ランドマークは逆さ改札。線路は壁にしない。5面中もっとも斜め・横断方向の流れを強くする。

Stage 5「朝をつなぐ灯り庭」:
地図帳の中心ページ。過去4面の小物が、何度も直されたランタンの光で仮接続される。主色は深い藍黒、琥珀、薄い朝焼け色、黒赤。中央には複数の光円を接続できる余白を残す。中景に過去小物の弱い反応、光の道、修理跡、残り火。外周に暗部、消えた街並み、複数ページの重なり、朝色が差すページ端。主ランドマークは最大の修理ランタン一つ。過去4面の象徴物を同格の主役として大量配置しない。明暗の安全地帯と危険地帯が一目で分かること。

5面全体の進行:
Stage 1は拾う、Stage 2は呼ぶ・近づく、Stage 3は守る・開ける、Stage 4は帰る方向を読む、Stage 5は灯りをつなぐ。色と光の意味もこの順に進化させる。ただし5面すべてを色違いの同じマップにしない。地面の大きな形、外周シルエット、主ランドマーク、動線を必ず変える。

禁止:
リアルな石畳、中世RPG村、ホラー墓地、写真紙テクスチャ、全面ディザ、高密度の細部、等間隔の装飾、読める文章、ロゴ、強い白発光、全Stage同じ構図、Stage 1だけ過剰な作り込み、UIやキャラクターを環境コンセプトへ描くこと。

環境コンセプトの後に、必ず5面の整合性表を作ってください。表には、象徴物、主色、光色、地面シルエット、主ランドマーク、動線、中央の静けさ、外周密度、他Stageとの差、共通素材、固有素材を記載してください。

最初の回答ではproduction素材へ分解せず、5面の環境ラインナップと整合性確認に集中してください。
```

# 9. 一括レビュー基準

## 5面全体

- [ ] 同じゲームの同じ世界に見える
- [ ] ドット密度と縮尺が揃っている
- [ ] Stage 1だけ品質が突出していない

# 10. 安全な次工程

5面一括生成後は、次の順で進める。

1. 5面横並びで整合性レビュー
2. 5面まとめて一回修正
3. 5面のgameplay compositeを一括作成
4. 5面のスマホ・タブレット・PC表示を一括確認
5. 5面共通アセットと固有アセットを一括分類
6. Stage 1〜5のpreview実装計画を作る
7. 実装は共通基盤から進め、production切替はStage単位で行う

「設計と画像生成は一括」「production昇格と実装切替は安全に段階的」が正しい分離である。
