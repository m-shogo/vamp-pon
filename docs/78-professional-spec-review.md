# Professional Spec Review

## 目的

Vamp Pon の仕様を、プロ制作目線でレビューする。

ここでは資料の量ではなく、仕様そのものを見る。

観点:

```txt
ゲームとして成立するか
スマホで遊べるか
MVP範囲が適切か
数値が検証可能か
実装時に迷わないか
破綻する仕様が混ざっていないか
```

---

# 1. 総合判定

```txt
Prototype 1 Spec: 95 / 100
Prototype 2 Spec: 88 / 100
Prototype 3 / MVP Spec: 82 / 100
Full Production Spec: 65 / 100
```

## 結論

Prototype 1には進める。

ただし、MVP全体を100%仕様と言うには、まだ以下が不足している。

```txt
Prototype別の確定数値表
データ契約
ランタイム状態仕様
敵/武器の衝突ルール
XPカーブの確定初期値
8分ウェーブの実装用テーブル
Go/No-Goと数値指標の接続
```

---

# 2. 良い仕様

## 2.1 コンセプトが短い

```txt
影を払い、記憶を拾い、朝まで残る。
```

これは強い。

ゲームの行動と世界観がつながっている。

## 2.2 MVPの問いが明確

```txt
仮素材でも、ユイで8分遊んで、もう一度遊びたいか？
```

この問いがあるので、仕様追加を止めやすい。

## 2.3 スマホ前提がある

```txt
縦持ち
仮想スティック
自動攻撃
必殺技1ボタン
3択カード
非アクティブ時ポーズ
```

PCヴァンサバの単純移植ではない点が良い。

## 2.4 やらないことが決まっている

```txt
ミチル
2ステージ目
10分full
詳細図鑑
PWA/Capacitor
課金/広告
```

ここはプロ目線でかなり良い。

---

# 3. 危ない仕様

## 3.1 10分案と8分案が過去資料で混在

最新は8分。

10分は将来full。

実装時は必ず8分を採用する。

## 3.2 ミチルが詳細仕様に残っている

過去資料にはミチルが細かく書かれている。

しかし最新MVPはユイのみ。

ミチルはMVP後。

## 3.3 MVP強く推奨が実装スコープに見える危険

以下は「入れてもよい」ではなく、Go判定後に検討するもの。

```txt
北極星のランタン進化
簡易図鑑画面
簡易実績画面
永続強化5種
自動必殺技設定
```

Prototype 1には入れない。

Prototype 3でも、必要なら一部後回し。

## 3.4 裏ストーリーが増えすぎる危険

裏ストーリーは魅力だが、戦闘テンポを止めると悪い仕様になる。

MVPでは以下に限定する。

```txt
カード1行
カプセル1行
リザルト1行
図鑑登録文
```

---

# 4. 仕様として足りなかったもの

## 4.1 Prototype別の数値境界

資料には方向性があるが、実装者が直接使う数値表が不足。

必要:

```txt
P1用数値
P2用数値
P3用数値
```

## 4.2 Data Contract

武器/敵/パッシブ/ウェーブ/進化のデータ構造が必要。

既に型定義案はあるが、仕様書としての正本が必要。

## 4.3 衝突/判定仕様

以下が曖昧だった。

```txt
敵接触ダメージ間隔
無敵時間
弾と敵の当たり判定
欠片取得範囲
吸引開始範囲
画面外スポーン距離
```

## 4.4 レベルアップ抽選の実装ルール

候補比率はあるが、以下が不足。

```txt
候補が3つ未満の時
同一ID重複禁止
Lv.MAX除外
枠満了時の新規候補禁止
回復候補の扱い
```

## 4.5 MVP acceptance criteria

MVP完成条件はあるが、数値指標と紐づく表が必要。

例:

```txt
初回Lv2: 60秒以内
初カプセル: 3:00±15秒
必殺技使用: 2〜4回
進化: 1回以上狙える
```

---

# 5. プロ目線の最終判断

## Prototype 1

仕様はほぼ十分。

不足は補完すれば100%。

## Prototype 2

仕様はかなり良いが、レベルアップ抽選/武器差/パッシブ反映のデータ契約が必要。

## Prototype 3 / MVP

方向は良い。

ただし、8分ウェーブと進化/カプセル/必殺技の数値仕様を正本化しないと、実装時に迷う。

## Full Production

まだ早い。

デザイン、サウンド素材、商用運用、分析、ストア対応が未検証。

---

# 6. 100%にするための補完対象

以下を追加する。

```txt
1. Prototype別 Spec Lock
2. Runtime Rules
3. Data Contract
4. Balance Target Matrix
5. MVP Acceptance Criteria
6. Spec Sign-off
```

これを追加すれば、Prototype 1仕様は100%。

MVP仕様も実装開始前として十分な精度になる。
