# 戦闘の気持ちよさ改善計画

Stage1画面完成度スプリントの次に行う、戦闘体験を80〜85点へ上げるための設計メモ。
素材量産ではなく、触った瞬間の反応、敵撃破、経験値回収、レベルアップ、進化/合体/覚醒の快感を一本のループとして整える。

## 調査からの採用方針

### 1. まずプロファイル、原因を見てから最適化する

Unity公式は、パフォーマンス問題を解く前に原因を特定することを推奨している。
Vamp Ponでは、Web版の段階でも「なんとなく重そう」ではなく、以下を分けて見る。

- 敵数によるCPU負荷
- パーティクル/透明スプライト/暗幕によるGPU overdraw
- UI更新頻度
- ドロップ/XP粒子の生成破棄
- 演出中のtween数

### 2. 2Dモバイルでは透明物の重なりを増やしすぎない

Unity公式は、GPU fill rate が問題になる場合、透明UI、粒子、スプライトのoverdrawが主要原因になりやすいとしている。
Vamp Ponは黒インク、光、紙片、パーティクルが多くなりやすいので、演出は派手にしつつも以下を守る。

- 常時出る背景霧は薄く少なくする。
- 撃破時の粒子は短命にする。
- 画面全体を覆う半透明レイヤーを重ねすぎない。
- レベルアップ/カットイン中だけ強い演出を使う。
- インク飛散は粒数ではなく、形・一瞬の拡大・音で気持ちよさを出す。

### 3. Sprite Atlas前提で素材カテゴリを分ける

Unity公式のSprite Atlas workflowでは、複数スプライトをAtlasへまとめ、目的ごとに整理する考え方が示されている。
Vamp PonではUnity移行時に以下のAtlas分類を想定する。

| Atlas | 対象 | 方針 |
|---|---|---|
| `atlas_ui_icons` | 武器/パッシブ/レアの小アイコン | 32/64px可読性優先 |
| `atlas_yui_core` | ユイの通常スプライト/カットイン関連 | 主人公は分離 |
| `atlas_stage1_enemies` | Stage1敵 | 役割差・同時表示数優先 |
| `atlas_stage1_fx` | インク/紙片/光/XP | 短命演出用 |
| `atlas_backgrounds_stage1` | Stage1背景 | 大きいので別扱い |

### 4. Addressablesは最初から重く使いすぎない

Addressablesはアドレス指定でローカル/リモート問わず非同期ロードし、依存やメモリ管理を助ける仕組み。
ただしStage1縦スライス時点では、最初から全素材をAddressables化しすぎると複雑になる。

Vamp Ponの推奨:

- Unity初期移行では、Stage1必須素材はビルド同梱でよい。
- キャラ/ステージが増え始めたらAddressablesを本格採用。
- 将来の追加ステージ/追加キャラ/イベント素材はAddressables候補。
- まずは「アドレスで参照できるID設計」をWeb版docsで固める。

### 5. Game feelは「tuning / juicing / streamlining」に分ける

Game feel研究では、気持ちよさを大きく以下へ分けて考えられる。

- tuning: 物体や移動の手触り調整
- juicing: 視覚/音/揺れ/一時停止で重要イベントを増幅
- streamlining: プレイヤーの意図を邪魔しない導線化

Vamp Ponでは、以下に置き換える。

| 分類 | Vamp Ponでの意味 |
|---|---|
| tuning | 移動速度、敵速度、攻撃間隔、XP吸引速度、敵HP |
| juicing | 撃破、ヒット、レベルアップ、進化、カットイン、SE |
| streamlining | カード選択、所持枠、回復ドロップ、必殺発動、リザルト |

### 6. Impact feelでは hit stop / sound coherence / camera control が重要

Impact feel研究では、ヒット感に強く関係しうる要素として、hit stop、音の一貫性、カメラ制御が挙げられている。
Vamp Ponでは以下を最優先にする。

- 敵撃破時の0.04〜0.08秒程度の軽いヒットストップ
- 強攻撃/進化/覚醒だけやや長い停止
- 小さな画面揺れは通常攻撃では控えめ、撃破/進化で強め
- 音は武器ごとに違いを出す
- 低音を入れすぎず、スマホスピーカーでも分かる中高域を優先する

## 戦闘快感ループ

Vamp PonのStage1で最初に完成させる快感ループは以下。

```txt
移動する
↓
敵が寄る
↓
武器が当たる
↓
敵が反応する
↓
倒れる
↓
インク/紙片/光が出る
↓
XPが吸い寄せられる
↓
音と小演出で回収が気持ちいい
↓
レベルアップ
↓
カード選択が気持ちいい
↓
武器が強くなる
↓
敵をもっと気持ちよく倒せる
```

このループが気持ちよくなるまで、キャラ数や敵図鑑数を増やしすぎない。

## 実装優先順位

### Phase 1: 敵撃破の手触り

目的: 1体倒すだけで気持ちいい状態にする。

やること:

- 撃破時に小さいインク破裂を出す。
- 敵ごとに消え方を少し変える。
- 紙片/インク粒/小さな光を短命で出す。
- 撃破時にXPが出る位置を見やすくする。
- 通常敵は軽い、エリート/ボスは重い演出にする。

採用基準:

- 敵が消えた瞬間が分かる。
- 粒子が背景や敵と混ざりすぎない。
- 10体同時撃破でも画面が汚くならない。
- 390x844で邪魔にならない。

避けること:

- 常時残る煙。
- 大量の長寿命パーティクル。
- 全敵同じ爆発。
- 暗すぎる黒粒子だけの演出。

### Phase 2: ヒット感

目的: 攻撃が当たっていることを目と音で分かるようにする。

やること:

- 命中時に敵へ短い白/薄黄フラッシュ。
- 武器ごとのhit sparkを分ける。
- black_ink_bottleは小さなインク跳ね。
- night_pencilは細い紙切れ/線の切り込み。
- streetlamp_ringは暖色リング。
- 連続ヒット時は演出を間引く。

採用基準:

- 攻撃が当たったか分かる。
- 連続ヒットでもうるさくない。
- 敵のシルエットを潰さない。

### Phase 3: XP回収

目的: レベルアップへ向かう快感を作る。

やること:

- XP粒子の吸い寄せを少し気持ちよくする。
- 近距離は速く、遠距離は弧を描く。
- 回収音を小さく重ねる。
- 連続回収時は音程/粒の明滅でテンポを出す。
- レベルアップ直前はゲージ反応を強める。

採用基準:

- XPを集めるだけで楽しい。
- 回収音がうるさくない。
- 低スペ端末で大量XPが重くならない設計。

### Phase 4: レベルアップと選択

目的: レベルアップが報酬として嬉しい状態にする。

やること:

- レベルアップ時に一瞬テンポを止める。
- 背景を少し暗くしてカードへ視線誘導。
- カード出現に時間差。
- 選択時にカードが確定する手応え。
- レア/良い選択肢は演出を少し強くする。

採用基準:

- カード3枚が読める。
- 選ぶ瞬間が気持ちいい。
- 画面全体が安っぽくならない。

### Phase 5: 進化/合体/覚醒

目的: 1プレイ中の最大報酬を作る。

やること:

- 進化/合体/覚醒は通常レベルアップと別格にする。
- 0.2〜0.4秒の強い間を作る。
- 画面中央に素材→完成品の流れを出す。
- カットインや光を使う。
- 完了後に新武器の初撃を強く見せる。

採用基準:

- プレイヤーが「今すごいことが起きた」と分かる。
- 説明を読まなくても報酬感がある。
- うるさすぎず、Vamp Ponの静かな夜の雰囲気を壊さない。

## 数値の初期案

Web版で試す初期値。
Unity移行時はプロファイルしながら調整する。

| 演出 | 初期値 | メモ |
|---|---:|---|
| 通常ヒットフラッシュ | 60〜90ms | 敵本体の読みやすさ優先 |
| 通常撃破hit stop | 40ms | 連続撃破時は間引き |
| エリート撃破hit stop | 70ms | 画面揺れ小 |
| ボス撃破hit stop | 120ms | 大演出用 |
| 通常撃破粒子寿命 | 250〜450ms | 短命 |
| XP吸引開始遅延 | 80〜160ms | 撃破→回収の気持ちよさ |
| XP吸引時間 | 220〜500ms | 距離で可変 |
| レベルアップ停止 | 120〜220ms | カード出現前の間 |
| 進化/覚醒停止 | 250〜400ms | 別格感 |
| 通常画面揺れ | 0〜1px | 基本は控えめ |
| 大撃破画面揺れ | 2〜4px | スマホ酔い防止 |

## Unity移行時の技術方針

### レンダリング

- URP 2D Rendererを第一候補にする。
- ただし2D Lightは常時多用しない。
- ランタンや進化演出など、意味のある箇所に限定する。
- 背景全体の暗さはライトではなく、アートと軽いoverlayで作る。

### アセット

- アイコン、敵、FX、背景、カットインでAtlasを分ける。
- Stage1必須素材は最初はビルド同梱でよい。
- 将来の追加キャラ/追加ステージからAddressables検討。
- 透明PNGは白フリンジ確認を必須にする。

### パフォーマンス

- Object Poolを前提にする。
- XP粒子、敵、ダメージ表示、FXは生成破棄しない。
- 同時表示数に上限を持つ。
- overdraw確認を行う。
- iOS/Androidの実機プロファイル前提で進める。

## Codex実装時の停止ルール

以下の場合は先に進まず報告する。

- 演出追加で敵やXPが見えなくなった。
- 粒子が増えすぎて画面が汚い。
- build/testが壊れた。
- 390x844でHUDが読めない。
- 既存の世界観から大きく外れた。
- パフォーマンス改善の名目で気持ちよさが落ちた。
