# Productization and Ops Plan

## 目的

Webプロトタイプが面白いと確認できた後、公開・運用へ進むために必要なことを整理する。

今は実装しない。

---

# 1. 開始条件

Productizationへ進む条件:

- Prototype 3 / MVP Stage 1が面白い
- スマホで重くない
- 本格デザインの方向が固まった
- 素材ライセンスが整理されている
- 継続プレイ価値がある

---

# 2. 公開形態候補

## Web公開

最初の候補。

必要:

- build
- hosting
- HTTPS
- スマホ確認

## PWA

Web公開後に検討。

必要:

- manifest
- icon
- offline方針
- install導線

## Capacitor / アプリ化

最後に検討。

必要:

- iOS/Android確認
- ストア素材
- プライバシーポリシー
- 署名
- 審査対応

---

# 3. 法務/文書

将来必要:

- プライバシーポリシー
- 利用規約
- 問い合わせ導線
- ライセンス表記
- クレジット

個人利用/非公開なら後回し。

公開するなら必須。

---

# 4. 分析イベント

入れるなら最小から。

候補:

- run_start
- run_end
- level_up
- capsule_get
- evolve
- ultimate_used
- game_over
- clear

注意:

- 個人情報を取らない
- 会話/入力文字を取らない
- 必要になってから入れる

---

# 5. クラッシュ/エラーログ

Web公開後に検討。

見るもの:

- 起動失敗
- Canvas/Phaser例外
- localStorage失敗
- モバイルブラウザ固有エラー

---

# 6. ストア素材

アプリ化するなら必要。

- 正式タイトル
- アイコン
- スクリーンショット
- 紹介文
- 年齢レーティング
- プライバシー項目

Prototype段階では不要。

---

# 7. 運用

公開後に必要:

- バージョン管理
- changelog
- 既知の不具合
- 問い合わせ管理
- セーブデータ互換

---

# 8. No-Go

以下ならProductizationへ進まない。

- 8分が面白くない
- スマホで重い
- 素材ライセンスが不明
- タイトルが未確定
- 継続プレイ価値がない

---

# 最重要

Productizationは、ゲームが面白いと分かった後にやる。

```txt
公開準備で面白さは作れない。
```
