# アプリゲーム前提への仕様補正

## 目的

Vamp Pon はアプリゲームとして作る。

そのため、PC/キーボード前提の Vampire Survivors ライクをそのまま持ち込まない。

以下をアプリ前提へ補正する。

```txt
操作
画面比率
UI密度
1プレイ時間
レベルアップ選択
必殺技発動
パフォーマンス
保存
セッション設計
実装技術
```

## 結論

アプリゲーム前提なら、MVP仕様はかなり変わる。

特に重要なのは以下。

```txt
縦持ち優先
片手操作も考慮
仮想スティック or スワイプ移動
ボタンは最大1つ
1プレイ10分は少し長い可能性
MVPは5分/8分/10分の3段階を検証
UIは大きく、文字は少なく
敵数と弾数はPCより抑える
途中中断/復帰を前提にする
```

---

# 1. 画面向き

## 候補

### 横持ち

良い点:

```txt
ヴァンサバに近い
視野が広い
敵の群れを見やすい
```

悪い点:

```txt
スマホで気軽に遊びにくい
片手操作しづらい
UI配置が窮屈になりやすい
```

### 縦持ち

良い点:

```txt
スマホアプリらしい
片手でも遊びやすい
短時間起動しやすい
SNS/カジュアルゲームに近い
```

悪い点:

```txt
横方向の視野が狭い
敵の囲まれ方が変わる
下から来る敵が強くなりすぎる
```

## 推奨

MVPは **縦持ち** を第一候補にする。

理由:

```txt
アプリゲームとして触りやすい
個人開発でUI検証しやすい
Vamp Ponの「基本ぼーっと遊べる」と相性が良い
```

ただし、ゲームロジックは横持ちにも転用できるようにする。

## 仮解像度

MVPの論理解像度:

```txt
縦持ち: 390 x 844 基準
横持ち検証: 844 x 390
```

実装では画面サイズに合わせてスケール。

# 2. 操作設計

## 操作候補

### 1. 仮想スティック

左下に仮想スティック。

良い点:

```txt
分かりやすい
移動方向を制御しやすい
ヴァンサバ系と相性が良い
```

悪い点:

```txt
親指で画面が隠れる
左下UIを置きにくい
```

### 2. 画面ドラッグ移動

指を置いた方向へ移動。

良い点:

```txt
片手でもいける
UIが少ない
```

悪い点:

```txt
細かい回避がやや難しい
操作感の調整が重要
```

### 3. タップ移動

タップ地点へ移動。

良い点:

```txt
簡単
```

悪い点:

```txt
ヴァンサバの避ける気持ちよさと合いにくい
混雑時に事故りやすい
```

## 推奨

MVPは以下。

```txt
第1候補: 仮想スティック
第2候補: 画面ドラッグ移動
タップ移動は不採用
```

## 操作仕様

```txt
左下: 仮想スティック
右下: 必殺技ボタン 1つ
攻撃: 完全自動
レベルアップ: カードをタップ
カプセル: 自動取得 or 接触取得
```

## 片手モード

MVPでは本格対応しない。

ただし、将来のために以下を避ける。

```txt
同時押し必須
長押し必須
複数ボタン
精密エイム
```

# 3. 必殺技のアプリ補正

## 問題

スマホで必殺技ボタンがあると、操作が忙しくなる。

特に左手で移動、右手で必殺技の場合、横持ちゲーム寄りになる。

## 方針

必殺技は以下のどちらか。

```txt
A. 右下1ボタン発動
B. 自動発動モードあり
```

MVPでは、設定として `autoUltimate` を用意する。

初期値は検討。

### 手動発動

良い点:

```txt
ピンチで使える
プレイヤーの判断がある
```

悪い点:

```txt
押し忘れる
スマホだと忙しい
```

### 自動発動

条件:

```txt
HP35%以下
周囲の敵数が一定以上
ゲージ満タン後に初めて被弾
```

良い点:

```txt
初心者向け
ぼーっと遊べる
```

悪い点:

```txt
狙って使えない
気持ちよさが少し落ちる
```

## 推奨

MVPでは以下。

```txt
手動ボタンあり
設定で自動発動ON/OFF
初期値は手動
```

ただし、チュートリアルなしでも分かるように、満タン時だけボタンを目立たせる。

# 4. 1プレイ時間の補正

## 10分は長い可能性

スマホアプリでは、10分はやや長い。

特に初回プレイで10分は重く感じる可能性がある。

## 候補

### 5分モード

良い点:

```txt
短い
検証が早い
初回体験に向く
```

悪い点:

```txt
武器進化まで届きにくい
ヴァンサバ的な育つ気持ちよさが薄い
```

### 8分モード

良い点:

```txt
スマホに収まりやすい
進化も入れやすい
10分より軽い
```

悪い点:

```txt
やや中途半端
```

### 10分モード

良い点:

```txt
ビルドが育つ
進化が入る
山が作りやすい
```

悪い点:

```txt
スマホでは長め
中断対策が必要
```

## 推奨

MVP実装では、内部的に時間を可変にする。

```txt
short: 5分
standard: 8分
full: 10分
```

最初の公開/検証では **8分** を第一候補にする。

ただし既存仕様の10分ウェーブは残し、8分版へ圧縮できるようにする。

## 8分版の考え方

```txt
0〜1.5分: 操作確認
1.5〜3分: 速い敵
3分: 初カプセル
3〜5分: 硬い敵/回り込み
5分: 2回目カプセル
5〜7分: 群れ
7分: 最終カプセル
7〜8分: クライマックス
```

# 5. UI密度の補正

## スマホで危険なもの

```txt
小さい文字
小さいアイコン
画面端の細かい情報
常時表示の説明文
多すぎるダメージ数字
長いカード説明
```

## ゲーム中UI

スマホでは以下だけ常時表示。

```txt
残り時間
HP
Lv
必殺技ボタン/ゲージ
```

武器/パッシブ一覧は、MVPでは下部に小さく置くが、読ませるUIにしない。

## レベルアップUI

カードは3枚まで。

スマホでは4択は避ける。

カード文言は短く。

例:

```txt
夜の鉛筆 Lv.2
ダメージ +4
```

裏ストーリー文は小さく1行。

読まなくても選べるようにする。

## リザルトUI

1画面に詰め込みすぎない。

スマホではタブ/セクション分けが必要。

MVPは以下で良い。

```txt
結果
ビルド
新発見
次の目標
```

# 6. パフォーマンス補正

## アプリで危険なもの

```txt
敵数が多すぎる
弾数が多すぎる
ドロップ欠片が多すぎる
パーティクルが多すぎる
ダメージ数字が多すぎる
毎フレーム重い探索
```

## 敵数上限

MVPスマホ向け初期上限。

```txt
通常敵 maxAlive 合計: 120〜160
欠片 maxAlive: 250
弾 maxAlive: 120
パーティクル: 控えめ
```

PCより抑える。

## 欠片統合

大量の欠片が出る場合、近い欠片を統合する。

例:

```txt
欠片1 x 5個
↓
欠片5 x 1個
```

## 敵探索

武器のターゲット探索は、毎フレーム全敵探索しない。

```txt
武器発射時だけ探索
距離計算は平方距離
必要なら空間分割
```

MVP初期は敵数が少なければ全探索でも可。

## フレームレート

目標:

```txt
60fps理想
最低30fps維持
```

スマホでは 30fps でも遊べるようにする。

# 7. アプリ保存/中断復帰

## 必須

スマホは中断される。

以下を考慮する。

```txt
アプリを閉じる
電話/通知で中断
画面ロック
バックグラウンド復帰
```

## MVP方針

MVPではラン中断保存までは重い。

ただし、最低限以下は必要。

```txt
アプリ非アクティブ時に自動ポーズ
復帰時にポーズ状態
リザルト到達時に保存
実績/図鑑/通貨は即保存
```

## ラン途中保存

後回し。

ただし、10分モードを採用するなら必要性が上がる。

8分以下なら、最初はなくても許容。

# 8. 技術選定補正

## Webゲームとして作る場合

```txt
Vite + TypeScript + Phaser
```

良い点:

```txt
開発が速い
ブラウザで確認できる
PWA/Capacitorでアプリ化できる可能性
```

リスク:

```txt
ネイティブ性能に劣る
ストア対応が別途必要
スマホ最適化が必要
```

## ネイティブ/Unityの場合

良い点:

```txt
アプリゲームとして王道
パフォーマンス/ストア対応が強い
```

リスク:

```txt
学習/実装負荷が上がる
Webフロント資産と離れる
個人開発で初速が落ちる
```

## 現時点の推奨

まずは以下。

```txt
Vite + TypeScript + Phaser でゲーム性検証
スマホブラウザで縦持ち検証
その後 PWA / Capacitor / ネイティブ移植を判断
```

理由:

```txt
今はデザイン未確定
ゲームロジック検証が先
個人開発では初速が大事
```

## 注意

最初から「アプリストア完成版」を作ろうとすると重い。

まずはスマホブラウザで遊べるプロトタイプを作る。

# 9. MVP仕様の補正まとめ

## 変更するもの

### 画面

```txt
縦持ち優先
390x844基準
```

### 操作

```txt
仮想スティック
必殺技1ボタン
自動発動設定あり
```

### 時間

旧:

```txt
10分
```

補正:

```txt
5分/8分/10分を切り替え可能
初期検証は8分推奨
```

### UI

```txt
常時表示を減らす
3択固定
長文を出さない
```

### パフォーマンス

```txt
敵数上限を設定
欠片統合
ダメージ数字控えめ
```

### 保存

```txt
非アクティブ時ポーズ
リザルト/実績/図鑑保存
ラン途中保存は後回し
```

## 変えないもの

```txt
移動中心
自動攻撃
経験値/欠片
レベルアップ
武器/パッシブ
記憶カプセル
進化
必殺技
裏ストーリー断片
```

# 10. アプリ前提で次に詰めること

デザイン以外で次に詰めるべきは以下。

```txt
1. 縦持ち用の当たり判定/出現方向補正
2. 8分版ウェーブ表
3. 仮想スティック仕様
4. スマホ用レベルアップカード仕様
5. パフォーマンス上限値
6. PWA/Capacitor/ネイティブ化の判断基準
7. 中断/復帰仕様
```

## 結論

アプリゲーム前提なら、Vamp Pon はより絞るべき。

```txt
縦持ち
短めセッション
片手でも遊べる操作
情報量少なめ
敵数を抑えて気持ちよく
自動攻撃 + 必殺技1ボタン
```

これが正しい方向。

Vampire Survivors の構造は使うが、PC版そのままではなく、スマホで触りやすい形に直す。
