# Why-first Scenario Design Rules

## 目的

Vamp Ponのシナリオ設計では、早く役に立つ形へ整える前に、必ず「なぜ」を潰す。

さらに、提案を無条件に肯定しない。

```txt
採用
保留
却下
```

を必ず分ける。

---

# 1. 反省点

過去の案では、以下の失敗があった。

```txt
先にそれっぽい結論を出す
先にキャラ表を作る
先に感動しそうな言葉を置く
先にドキュメント化する
ユーザーの案をすぐ肯定する
```

これはシナリオにもコードにも向かない。

Vamp Ponでは、以下を先に考える必要がある。

```txt
理由
理屈
代償
伏線
回収
ゲーム仕様との一致
採用/保留/却下
```

---

# 2. 今後の基本順序

シナリオ案は必ず以下の順で作る。

```txt
1. 出来事
2. なぜ起きる？
3. 誰の誤解？
4. 何の代償？
5. どの小物に残る？
6. いつ伏線として見せる？
7. いつ回収する？
8. 回収後、過去の見え方がどう変わる？
9. ゲーム仕様と一致している？
10. 2以降に何を残す？
11. 採用/保留/却下のどれか？
```

この11問を通らない案は、正本化しない。

---

# 3. まず問うべき「なぜ」

## 世界法則のなぜ

```txt
なぜ黒インクは誤解を固定するのか
なぜ固定された誤解は襲ってくるのか
なぜ倒すと意味片になるのか
なぜ朝まで残る必要があるのか
なぜ朝になると仮接続がほどけるのか
なぜ地図帳には確定するのか
```

## キャラのなぜ

```txt
なぜユイは持ち主を間違えないのか
なぜアサは名前を扱うのか
なぜナギは理由をしまうのか
なぜミチルは場所を読むのか
なぜトモリは朝まで灯すのか
```

## アイテムのなぜ

```txt
なぜ鉛筆が武器なのか
なぜ名札が重要なのか
なぜ箱は閉じているのか
なぜ切符は片方だけなのか
なぜランタンは直されているのか
```

## 長期伏線のなぜ

```txt
なぜ未配達の封筒を今出すのか
なぜ四つ折りの地図を今は開かないのか
なぜ影系統を名前で出さないのか
なぜ背表紙系統はSeedだけなのか
```

---

# 4. 伏線の作り方

伏線は「後で使うために置くもの」ではない。

伏線は、初見でも自然に存在し、回収後に意味が変わるもの。

良い伏線:

```txt
初見: かわいい小物
1作内回収後: 誰かの誤解をほどく証拠
シリーズ後: 別系統の存在や別の読み方を示す痕跡
```

悪い伏線:

```txt
初見: 意味深なだけ
回収後: 急に説明で回収
続編予告として露骨
```

---

# 5. 小物伏線の必須条件

重要小物は必ず以下を持つ。

```txt
表の効果
初見の意味
1作内の隠された意味
シリーズ後に変わる意味
持ち主
誤解
反転
回収タイミング
残す余白
```

例:

```txt
片方だけの切符
表の効果: 移動/速度系
初見の意味: 帰れなかった証拠
1作内の意味: 帰る予定があった証拠
シリーズ後の意味: 別のページ束へ続く駅名が薄く残る
持ち主: ミチル周辺
誤解: 帰り道を残せなかった
反転: 裏に帰りの印がある
回収: Page 4
余白: 別の駅名が薄く読める
```

---

# 6. 考察の気持ちよさ

考察の気持ちよさは、謎が多いことではない。

以下が気持ちいい。

```txt
最初から見えていた
でも意味を間違えていた
後で意味が変わる
過去のプレイ体験まで変わる
シリーズ後にさらに意味が変わる
```

例:

```txt
ずっと拾っていた欠片
→ 経験値ではなく、固定された誤解から剥がれた意味片だった

ずっと使っていたランタン
→ トモリが直し続けた灯りだった
→ さらに修理跡の一部が別系統のものだった

ずっと倒していた影
→ 読まれたくない痛みではなく、固定された誤解そのものだった
```

---

# 7. 早く形にするタイミング

早く形にしてよいのは、以下を満たした後。

```txt
世界法則と矛盾していない
ゲーム仕様と一致している
小物に証拠がある
キャラの誤解と反転がある
順番の因果がある
後で回収した時に過去の見え方が変わる
採用/保留/却下が判断済み
```

この前に形にすると薄くなる。

---

# 8. 採用判断

## 採用する案

```txt
理屈が通る
ゲームとして気持ちいい
小物で伏線化できる
順番の因果がある
回収後に意味が反転する
2以降の邪魔をしない
```

## 保留する案

```txt
感情は良いが理屈が未確定
設定は良いがゲーム仕様にまだ接続していない
長期Seedとして使えるが1作目では重い
```

## 却下する案

```txt
雰囲気だけ良い
悲しいだけ
説明でしか回収できない
ゲーム仕様と関係ない
作品の表面要素に似すぎている
続編予告として露骨
```

---

# 9. 提案時のルール

今後、アイデアを出す時は必ずこの形にする。

```txt
案
採用/保留/却下
理由
弱点
補強するなら何が必要か
ゲーム仕様との接続
伏線として置ける小物
回収後に変わる意味
```

肯定だけで進めない。

---

# 10. 今後の作業手順

今後、シナリオを考える時は以下の順にする。

```txt
1. 因果ロジック
2. 欠片/黒インク/朝リセットの理屈
3. 5人の役割の物理的理由
4. Stage 1〜5の伏線配置
5. Stage 6〜15の真相回収
6. 50Stage拡張レール
7. シリーズ後に意味が変わるSeed
```

キャラ表や感動台詞は後。

先に理屈。

---

# 11. 最重要

Vamp Ponのシナリオでは、必ずこれを守る。

```txt
なぜ？に答えられないものは、まだ採用しない。
```

そして、答えは説明台詞ではなく、できるだけ以下に埋める。

```txt
アイテム
敵の挙動
地図帳
朝リセット
武器進化
リザルト文
背景の小物
```

これが、Vamp Ponを考察して気持ちいいゲームにするためのルール。
