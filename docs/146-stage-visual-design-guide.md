# Vamp Pon Stage Visual Design Guide v1

## 0. 文書の役割

この文書は、Vamp Pon の Stage 1〜5について、背景制作、画面モック、アセット分解、ブラウザ表示、ゲーム実装の判断基準を固定する正本である。

世界観を増やすための資料ではない。

```txt
何を描くか
何を描かないか
どこを静かにするか
どこに意味を置くか
スマホとブラウザでどう見せるか
```

を制作可能な粒度へ落とす。

関連資料:

- `docs/145-stage-1-to-5-emotional-beat-map.md`
- `docs/pixel-art/`
- `assets/reference/backgrounds/stage1_night_tile_reference.png`

現在の背景参照と既存背景は production 正本ではない。新しい画面基準が確定するまでは `gameplay placeholder` として扱う。

# 1. ワンページ要約

## ステージデザインの核

Vamp Pon のステージは「紙模様の床」ではない。

```txt
誰かが覚えていた場所
↓
意味だけが抜け落ちる
↓
黒インクが誤解を固定する
↓
ユイが欠片を拾い、朝まで仮接続する
```

という「場所の記憶」である。

各Stageは以下の一つを強い象徴として持つ。

| Stage | 象徴 | 感情 | プレイ上の動詞 |
|---:|---|---|---|
| 1 | 欠片 | 拾う気持ちよさ | 追う |
| 2 | 名札 | 名前が読めない不穏さ | 近づく |
| 3 | 箱 | 開けたい／守りたい葛藤 | 選ぶ |
| 4 | 切符 | 帰り道が読めない切なさ | 流れに乗る |
| 5 | 灯り | すべてが少しつながる感動 | つなぐ |

## 背景制作で絶対に守ること

1. プレイヤー、敵、弾、欠片、危険予告を背景より優先する。
2. 画面中央の戦闘面は静かにする。
3. 世界観は主に中景、外周、ランドマークで見せる。
4. 各Stageは色だけでなく、シルエット、動線、象徴物を変える。
5. 細かい紙目を全面に貼らない。
6. 390×844だけで完成扱いにせず、PCブラウザとタブレットの外側表示まで設計する。
7. 背景単体ではなく、UI、ユイ、敵20体、弾、欠片を載せた画面で評価する。

# 2. 参考作品から借りる設計原則

作品の見た目を直接模倣しない。以下の設計思想だけをVamp Ponへ翻訳する。

## Eastward

- 町、道、広場、外周が一目で分かる場所構成
- 情報量がありながら、歩ける場所が読める
- 一画面に記憶に残るランドマークがある

Vamp Ponでは密度を約7割へ落とし、戦闘面を広く取る。

## Beacon Pines

- 可愛い形の中に静かな不穏さがある
- 小物が装飾ではなく、物語の手掛かりになる
- 本や言葉のモチーフが説明文なしでも伝わる

## Carto

- 地図、道、ページの継ぎ目を分かりやすい記号へ整理する
- 背景そのものを「読む」楽しさを作る
- 世界の断片が接続する印象を作る

## Children of Morta

- 暗所でもプレイヤーと敵を見失わない
- 光源、安全地帯、危険地帯の差を明確にする
- 背景の暗さではなく、値と光の階層で夜を表現する

## Minute of Islands

- 一つの象徴物が場所全体の印象を決める
- ステージを一枚絵として記憶させる
- 世界設定を小物の数ではなく、構図で示す

# 3. 共通画面設計

## 3.1 画面の三層

### 戦闘床

プレイヤー、敵、弾、欠片が重なる層。

- 低コントラスト
- 大きな色面
- 細線を減らす
- 明暗差を急に作らない
- 強い輪郭を置かない

### 中景

場所の意味を伝える層。

- 小物
- 道の線
- 低い紙草
- 小さなインク溜まり
- 壊れた家具
- Stage固有の記号

### 外周・ランドマーク

画面を記憶させる層。

- 紙の家
- ページ端
- 大きな箱
- 改札
- ランタン
- 暗闇へ落ちる裂け目

戦闘床よりコントラストを上げてよいが、プレイヤー付近へ侵入させない。

## 3.2 密度の基準

画面内の面積比を目安として固定する。

| 区域 | 目安 | 内容 |
|---|---:|---|
| 静かな戦闘床 | 55〜65% | 無地に近い床、大きな薄い染み |
| 軽い装飾 | 20〜25% | 紙片、道線、足跡、小さな小物 |
| 強いランドマーク | 10〜15% | 家、箱、改札、ランタン、ページ端 |
| 強い演出 | 最大5% | 発光、裂け目、強いインク、イベント物 |

## 3.3 視認性順位

画面上の視認性は次の順位を崩さない。

```txt
危険予告
プレイヤー
敵
攻撃・必殺技
回復・重要ドロップ
記憶の欠片
ギミック
背景ランドマーク
小物
床の質感
```

背景が上位要素と同じ明度、彩度、輪郭強度を持ってはいけない。

## 3.4 紙・絵本風ドットの成立条件

紙らしさを細かいノイズで作らない。

使うもの:

- 少し歪んだ輪郭
- 不均一な直線
- 大きく薄い色むら
- 折れ、破れ、重なり
- 紙片の厚みを示す1〜2pxの縁
- 手描きの地図線

避けるもの:

- 全面に均一な紙ノイズ
- 細かい斑点の大量配置
- 高密度ディザ
- 全タイルに同じ傷
- 背景と敵の輪郭を同じ黒で描く

# 4. スマホ・タブレット・PCブラウザ対応

## 4.1 基準画面

ゲームプレイの正本は `390×844` の縦画面とする。

ただし、これは最小のコア表示領域であり、唯一の完成サイズではない。

```txt
core gameplay viewport: 390×844
safe gameplay aspect: portrait
extended world: browser / tabletの余剰領域
browser shell: canvas外側の世界観表示
```

## 4.2 表示モード

### A. スマホ縦

- 390×844基準をFIT
- ノッチ、ホームインジケータ用safe areaを確保
- 操作UIはコア領域内
- 背景ランドマークをUI直下へ置かない

### B. タブレット縦

- コア領域のゲーム倍率を優先
- 左右の追加領域へ背景とランドマークを広げる
- 敵spawn範囲や判定を安易に広げない
- 同じプレイバランスを維持する

### C. PCブラウザ縦ウィンドウ

- コア領域を中央へ配置
- 左右余白へ紙の層、夜の街、ページ端を表示
- 真っ黒な余白や単色帯を完成形にしない
- キーボード操作説明はゲーム面を圧迫しない外装側へ置ける

### D. PCブラウザ横長

ゲームロジックの可視範囲を横長へ変更しない。

```txt
左外装 | 390×844コアゲーム | 右外装
```

左右には以下を配置できる。

- Stage名
- 短い物語Seed
- 操作表示
- 図鑑進行
- 紙の家や街灯の遠景
- ページの重なり

戦闘に影響する敵、欠片、ギミックはコア外へ出さない。

### E. 低いブラウザウィンドウ

- FIT縮小を許容
- UI文字の最小可読サイズを検証する
- 高さが不足した時に上部・下部UIが重ならない
- ブラウザのアドレスバー出入りでレイアウトを再計算する

## 4.3 Overscan

背景素材はコア画面ぴったりで切らず、周囲にoverscanを持たせる。

推奨:

```txt
core: 390×844
visual mock master: 540×960以上
background composition master: 720×1280以上
```

この余剰領域は、ブラウザでの左右表示、カメラ揺れ、画面遷移、端末差へ使う。

重要物を端へ置かない。

## 4.4 Safe zone

390×844内の目安:

```txt
上部 0〜96px     HUD優先
中央 96〜680px   主戦闘面
下部 680〜844px  操作UI優先
左右 0〜48px     外周演出とspawn警告
```

ランドマークはHUDとスティック・必殺ボタンの背後を避ける。

## 4.5 ブラウザ外装

canvas外側もVamp Ponの世界として扱う。

共通外装:

- 深い藍黒の夜
- 薄い紙の層
- 大きくぼかした地図線
- 低彩度の街灯
- Stage色の弱い縁光

禁止:

- 純黒一色
- コア画面の単純な拡大ぼかし
- 左右へ同じ絵を鏡像配置
- 外装側の強いアニメーション
- ゲーム面より明るい装飾

# 5. Stage 1〜5 ビジュアルガイド

## Stage 1: ちぎれた夜の広場

### 一言コンセプト

忘れられた小さな街の広場が、地図帳の一ページとして夜に残っている。

### 役割

- 世界への入口
- 移動、攻撃、拾得を学ばせる
- 欠片を追うだけで気持ちよくする

### 見た目の核

- 青灰色の静かな紙広場
- 外周に紙の家と鉛筆街灯
- ページの裂け目から別の紙層が見える
- 淡い古紙金の記憶の欠片

### レイアウト

```txt
外周: 紙の家 / 街灯 / ページ端
中景: ベンチ / ポスト / 薄い地図線
中央: 広い静かな戦闘床
```

中央へ家や大物を置かない。

### 動線

欠片の連続取得で淡い軌跡が一時表示され、次に進みたい方向を自然に示す。

### ランドマーク候補

- 折れた鉛筆街灯
- 名前が消えたポスト
- ページ端の裂け目
- 小さな紙の家
- インクに半分沈んだベンチ
- 巨大な薄い地図の円

### 色

- 主色: 青灰 `#596078`相当
- 暗部: 青紫黒
- 光: くすんだ古紙金
- 危険: 暗い赤紫を少量

### NG

- 石畳にする
- 地図線を全面に均等配置する
- 欠片と同じ金色を背景に多用する
- 家を細密に描き込みすぎる

### 優先度

P1最優先。

---

## Stage 2: 名前をなくした札庭

### 一言コンセプト

空白の名札が植物や標識のように育つ、静かな庭。

### 見た目の核

- 吊られた名札
- 書いて消した跡
- 名札を避ける影
- 葡萄紫と薄い藤色

### レイアウト

中央は空け、名札の群生を複数の円形中景として置く。

### 動線

名札の近くで戦うとSeedや報酬が進む。安全な余白と危険な名札群を往復する。

### ランドマーク候補

- 巨大な空白名札
- 糸が絡んだ名札の木
- 消し跡だらけの掲示板
- 名前が切り取られた門

### NG

- 墓地そのものにする
- ホラーの血文字へ寄せる
- 読める名前を大量に置く

### 優先度

P1.5。

---

## Stage 3: 月箱の保管庫

### 一言コンセプト

開けてはいけない箱を守るために積み重ねられた、夜の紙保管庫。

### 見た目の核

- 月の印がある中央箱
- 焦茶紫の厚紙
- くすんだ封蝋赤
- 内側を向く鍵穴

### レイアウト

中央または準中央に大きな月箱を置き、周囲の箱山は硬い壁ではなく減速・視界差として使う。

### 動線

箱へ近づくと開封が進み敵が強化。離れると安定する。開ける／守るの選択を移動だけで作る。

### NG

- 完全な迷路にする
- 小箱を画面全面へ並べる
- 中身を早期に明示する

### 優先度

P2。

---

## Stage 4: 逆さ改札と帰り線

### 一言コンセプト

行き先が消え、帰る向きだけが逆に残った紙の駅と地図。

### 見た目の核

- 切符でできた床
- 手描きの線路
- 逆方向の矢印
- 行き先が空白の改札

### レイアウト

複数の線が画面を横切る。線は壁ではなく、速度と危険予告のガイドとして扱う。

### 動線

点灯した帰り線へ乗ると移動と吸引が補助されるが、敵も同じ線を使う。

### NG

- リアルな駅の再現
- 細い線を大量に交差させる
- 線路を通行不能壁にする

### 優先度

P2。

---

## Stage 5: 朝をつなぐ灯り庭

### 一言コンセプト

これまでの小物が、何度も直されたランタンの光で一つの地図へ戻る場所。

### 見た目の核

- 深い藍黒
- 琥珀のランタン
- 明るい安全地帯
- 暗部から湧く影
- 名札、箱、切符、欠片の反応

### レイアウト

複数のランタンを離して置き、光の円を順に接続する。

### 動線

安全な灯りと高報酬の暗部を往復する。灯りに籠もるだけを最適解にしない。

### NG

- 全画面を明るくする
- 発光を白一色にする
- 過去小物を同時に大量表示する

### 優先度

P1終盤〜P2。

# 6. 共通アセット設計

## 6.1 分解単位

```txt
base_floor
floor_variants
decals
props
landmarks
page_edges
ambient_effects
gimmick_objects
browser_shell
```

## base_floor

- ループ可能
- 最も低コントラスト
- Stageごとに1〜2種

## floor_variants

- 大きな薄い染み
- 破れ
- 紙の重なり
- 地図線の少ない差分

同じ柄を格子状に並べない。

## decals

- 足跡
- 小さな紙片
- 薄いインク
- 消し跡

透過素材として配置密度を制御する。

## props

- 街灯
- ベンチ
- ポスト
- 名札
- 小箱
- 切符標識

当たり判定なしを基本とする。

## landmarks

- 紙の家
- 巨大名札
- 月箱
- 改札
- 中央ランタン

1画面に同格の大物を複数置かない。

## page_edges

- ページ端
- 裂け目
- 下層の紙
- 黒インクのページ間

ブラウザoverscanと外装へ流用する。

## ambient_effects

- 紙粉
- 小さな光
- インク煙
- 弱い灯り揺れ

戦闘より目立たない速度と明度にする。

## browser_shell

- PC左右余白
- タブレット追加領域
- Stage別の弱い外装差分

ゲームプレイ判定を持たない。

# 7. Stage 1 本命実装候補

## 7.1 完成画面

中央に静かな青灰色の紙広場。ユイの周囲には強い線を置かない。

中景に薄い地図線、破れた紙草、小さなベンチ、ポストを置く。

外周には丸い紙の家、鉛筆街灯、ページ端を置き、場所の記憶であることを示す。

黒インク影は青紫黒。欠片は古紙金。ユイの暖色点と競合しないよう、欠片は輪郭より脈動で見せる。

## 7.2 最初に作る素材

### 必須モック

1. Stage 1 base floor
2. 大きな薄い染み差分 3種
3. 薄い地図線デカール 3種
4. ページ端 2種
5. 鉛筆街灯 2種
6. 紙の家 2種
7. ベンチ 1種
8. 名前なしポスト 1種
9. 小さな紙草 3種
10. ブラウザ左右外装 1セット

### モックへ同時配置するもの

- ユイ
- ポン影20体前後
- ふくらみポン影2〜3体
- 夜の鉛筆弾
- 記憶の欠片20個前後
- 上部HUD
- 左下スティック
- 右下必殺ボタン

背景だけのレビューを禁止する。

## 7.3 使用禁止装飾

- 読める文章
- 強い星柄
- 金色の街灯を大量配置
- 細密な窓
- 白い紙片の大量散布
- 等間隔の石・草・染み
- 高彩度の花

## 7.4 品質ゲート

次のすべてを満たすまでproduction候補へ昇格しない。

- 390×844でユイが一秒以内に見つかる
- 敵20体でも共通敵2種を判別できる
- 欠片が床模様と混同しない
- 弾の軌道が背景線と重ならない
- PC横長でも左右が未完成の黒帯に見えない
- タイル境界を3秒以内に指摘できない
- Stage 2へ色替えだけで流用できない固有構図がある

# 8. カラースクリプト

| Stage | 主色 | 補助色 | 光 | 危険色 | 感情 |
|---:|---|---|---|---|---|
| 1 | 青灰 | 青紫黒 | 古紙金 | 暗赤紫 | 静かな入口 |
| 2 | 葡萄紫 | 薄藤 | 白紙色 | 黒紫 | 読めない不穏 |
| 3 | 焦茶紫 | 封蝋赤 | 月白 | 暗い朱 | 葛藤と保護 |
| 4 | 青緑黒 | 褪せ水色 | 裏面橙 | 冷白 | 迷いと帰路 |
| 5 | 深藍黒 | 琥珀 | 朝焼け淡黄 | 黒赤 | 接続と朝 |

Stage 1から5へ向かい、光の意味を「拾う対象」から「場所をつなぐ力」へ変える。

---

# 9. やってはいけないこと

- 背景を一枚の大きな生成画像だけで完成扱いする
- 390×844だけ作り、PC左右を黒帯のままにする
- 夜を明度不足で表現する
- 中央へランドマークを詰める
- UI背後に強い線や発光を置く
- 紙目を全面ノイズとして貼る
- 同じデカールを等間隔配置する
- Stage差を色変更だけで作る
- 小物をストーリー説明文の代わりに大量配置する
- 敵と背景の輪郭色を同じ強さにする
- 弾の予告線と地図線を同じ太さ・色にする
- 外装側をゲーム面より派手にする
- ブラウザ幅によって戦闘範囲やspawn量を変える
- ランドスケープを理由にゲームロジックの可視範囲を広げる

# 10. レビューチェックリスト

## 世界観

- [ ] 紙模様ではなく、場所の記憶に見える
- [ ] Stage固有の象徴物が一つに絞られている
- [ ] 可愛さと不穏さが同時にある

## 戦闘視認性

- [ ] ユイを即座に見つけられる
- [ ] 敵、弾、欠片、危険予告の順位が守られている
- [ ] 中央が静かである
- [ ] 夜でも暗すぎない

## 構図

- [ ] 中央、中景、外周の役割が分かれている
- [ ] ランドマークが一つ強く見える
- [ ] 画面端にoverscanがある

## 反復

- [ ] タイル境界が目立たない
- [ ] 同じ小物が等間隔に並んでいない
- [ ] 大・中・小の変化がある
