# AIエージェント作業ルール

このリポジトリでAIエージェントが作業するときのルール。

## 対象範囲

作業対象はこのプロジェクトのみ。

ローカル前提パス:

```bash
/Users/m-shogo/Developer/personal/vamp-pon
```

このプロジェクト外のファイル・ディレクトリ・リポジトリは触らない。

## 常にコミット・プッシュする

変更したら、作業単位ごとに必ずコミットしてプッシュする。

ローカル作業の場合:

```bash
git status
git add .
git commit -m "docs: describe change"
git push
```

GitHub APIで直接ファイルを作成・更新する場合も、1変更ごとにコミットとして残す。

## 大きい作業は分割する

大きい変更を1回でまとめない。

推奨単位:

- docs追加
- セットアップ追加
- 1 system追加
- 1 entity追加
- 1 UI追加
- 1 bug fix

## 既存仕様を勝手に変えない

仕様を変える場合は、先にdocsを更新する。

特に以下は勝手に変えない。

- ゲームの核
- 前後左右中央の危険エリア設計
- MVPスコープ
- 技術スタック
- 作らないもの

## 報告を分ける

作業後は以下を分けて報告する。

- 完了
- 未完了
- 未検証
- 変更ファイル
- 実行したコマンド
- 次にやるべきこと

## 完了と言い切らない条件

以下の場合は、完了ではなく未検証と書く。

- dev起動していない
- buildしていない
- typecheckしていない
- ブラウザで見ていない
- 挙動確認していない

## ゲームを複雑にしすぎない

面白そうな追加より、完成に近づく追加を優先する。

MVP前に避けるもの:

- 武器大量追加
- キャラ大量追加
- ガチャ
- 課金
- アカウント
- オンライン
- スマホ最適化
- 複雑な永続成長
- 凝った素材制作

## Sceneに全部書かない

`MainScene.ts` に全部詰め込まない。

処理は役割ごとに分ける。

- `scenes/` は画面・状態
- `entities/` はプレイヤー、敵、弾
- `systems/` は戦闘、敵湧き、危険エリア判定
- `data/` は敵・武器・強化の数値
- `ui/` はHP、経験値、危険エリア表示

## 独自性を守る

Vamp Pon の独自性は、前後左右中央の危険エリアを見ること。

実装で迷ったら、次の問いに戻る。

## 命名メモ

以前の仮称「5戦線」は硬い。

今後はユーザーに説明するとき、基本は以下の表現を使う。

- 前後左右中央
- 5方向
- 5エリア
- 危険エリア
- 危険ゾーン

必要なら内部実装名だけ `front` / `area` / `zone` を検討する。
