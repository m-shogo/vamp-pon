# Unity移行準備チェックリスト

Vamp Pon のWeb版は、Unityへ移行する前に「仕様・画面・素材・気持ちよさ」を固めるための検証場として扱う。
Unity移行は100点まで待たず、Stage1縦スライスが80〜85点相当になった段階で開始する。

## 基本方針

- Unity移行は完成後の移植ではなく、Stage1の勝ち筋が見えた段階で始める。
- Web版で固めるのは、画面・仕様・データ・素材基準・演出タイミング。
- Web版で作り込みすぎると、Unity側で作り直す戻しが増える。
- Unity移行直後は一時的に完成度が下がる前提で進める。
- 移行前に、390x844の正解スクショと実装仕様を残す。

## 移行開始の目安

| 項目 | 目安 |
|---|---:|
| 現在地 | 60〜70点台 |
| Stage1画面完成度スプリント後 | 70〜78点 |
| 戦闘気持ちよさスプリント後 | 80〜85点 |
| Unity移行開始ライン | 80〜85点 |
| Unity版Stage1再現直後 | 75〜85点 |
| 商用MVP | 90点 |
| ストア品質 | 95点以上 |

## Unity移行OK条件

### 画面

- [ ] 390x844縦画面でStage1戦闘画面が成立している。
- [ ] HUDの時間、HP、Lv、欠片、必殺ゲージが読める。
- [ ] 下部インベントリが邪魔にならず、32px級アイコンでも意味が読める。
- [ ] レベルアップカード3枚が読める。
- [ ] カプセル報酬画面が破綻していない。
- [ ] リザルト画面で勝ち/負け/成長が伝わる。
- [ ] Top / StageSelect / Battle / LevelUp / Result の最低導線がある。

### Stage1ゲーム体験

- [ ] Stage1が8分前後で成立している。
- [ ] 序盤が寂しすぎない。
- [ ] 中盤で武器やパッシブの成長が分かる。
- [ ] 終盤で敵圧と報酬の盛り上がりがある。
- [ ] 勝ち/負けの意味が分かる。
- [ ] もう一度遊ぶ理由が最低限ある。

### 戦闘の気持ちよさ

- [ ] 敵撃破時の消滅演出が気持ちいい。
- [ ] ヒット時の反応が分かる。
- [ ] XP回収が気持ちいい。
- [ ] レベルアップ演出がご褒美になっている。
- [ ] 進化/合体/覚醒の最低1つが「来た」と分かる。
- [ ] 被弾が分かりやすい。
- [ ] 必殺/暴走の発動タイミングが分かる。
- [ ] SEなしでも成立し、SEありで一段気持ちよくなる設計になっている。

### 素材

- [ ] 主要武器アイコンが32pxで読める。
- [ ] 主要パッシブアイコンが32pxで読める。
- [ ] 主要レアアイコンが32pxで読める。
- [ ] UI枠、文字、レア枠を素材へ焼き込んでいない。
- [ ] 透明PNGの白フリンジがない。
- [ ] 生成素材は `public/assets/prototypes/` 配下に整理されている。
- [ ] `public/assets/sprites/` を再利用・再作成していない。
- [ ] test-pack止まりとruntime採用済みの区別が分かる。

### キャラクター

- [ ] ユイの基本スプライトが実画面で読める。
- [ ] ユイの通常カットインがある。
- [ ] ユイの固定事項が守られている。
  - [ ] ランタンは本人の右手。
  - [ ] バッグ紐は右肩から左腰。
  - [ ] バッグ本体は左腰。
- [ ] 次キャラ/相棒候補としてアサの扱いが整理されている。

### エネミー

- [ ] Stage1に出る敵が5〜6種類以上ある。
- [ ] 追尾、突進、群れ、硬い敵、報酬敵、ボス/エリートの役割差がある。
- [ ] 64px相当でも役割差が読める。
- [ ] 敵素材は8x6/180pxセル/48セルなどの検査を通している。
- [ ] edge touch / empty cell / center jitter の確認がある。

### データ構造

- [ ] weapons / passives / rareItems / evolutions / enemies / stages の責務が分かれている。
- [ ] runtime ID と表示名のズレが把握されている。
- [ ] Unity移行時にIDを変更したいものは移行メモに残す。
- [ ] セーブ互換が必要なIDはWeb版では安易に変更しない。
- [ ] 進化/合体/覚醒条件がデータで読める。

### 永続要素

- [ ] 負けても進む導線がある。
- [ ] 永続強化の方向性が決まっている。
- [ ] キャラ経験値と基礎パラメータ強化の違いが整理されている。
- [ ] 強化リセットの方針がある。
- [ ] 図鑑/実績/記憶の欠片が報酬として意味を持つ。

### Unity移行用資料

- [ ] 390x844の正解スクショを保存する。
- [ ] 画面ごとのUI配置仕様を残す。
- [ ] Stage1の敵出現テンポを残す。
- [ ] 武器/パッシブ/レア/進化の採用リストを残す。
- [ ] 素材の採用済みパスを残す。
- [ ] Unityで置き換えたい技術要素を残す。
- [ ] Web版で妥協した点を残す。

## 移行前にやらないこと

- 20キャラ分の実装。
- 50ステージ分の実装。
- 敵図鑑の大量埋め。
- 課金/広告の細部設計。
- Unityで作り直す前提の大規模UIリファクタ。
- 3D化への寄り道。
- 既存素材の大量削除。

## Web版で優先して完了させること

1. Stage1画面完成度スプリント
   - 主要アイコン
   - Stage1背景
   - ユイ通常カットイン
   - Stage1新敵1体
2. 戦闘気持ちよさスプリント
   - 敵撃破演出
   - XP回収
   - ヒット感
   - 進化/合体/覚醒演出
   - SE方針
3. Unity移行準備
   - 正解スクショ
   - データ一覧
   - 画面仕様
   - 採用素材一覧
   - 移行時リネーム候補

## 移行時リネーム候補

Web版では互換性を優先してIDを維持するが、Unity移行時には表示名や役割に合わせたIDへ整理してもよい。

| Web runtime ID | 現表示/役割 | Unity移行時候補 | 方針 |
|---|---|---|---|
| `old_ticket` | あったか靴 / 移動速度パッシブ | `warm_shoes` | Unity移行時にデータ移行できるなら整理候補 |
| `name_tag` | 覚醒素材候補 | `name_tag` | 維持候補 |
| `dawn_ticket` | 復帰/救済レア候補 | `dawn_ticket` | 役割確定後に採用判断 |

## 完了判定

Unity移行開始前に、以下の問いへ全部答えられる状態にする。

- Stage1は何が楽しいのか。
- 初回プレイの1分目で何が起きるのか。
- 3分目で何が強くなったと分かるのか。
- 8分目で何を達成するのか。
- 負けても何が残るのか。
- ユイを使う理由は何か。
- Unityで最初に再現すべき画面はどれか。
- Unityで捨ててよいWeb版実装はどれか。
- Unityでも守るべき見た目基準はどれか。
