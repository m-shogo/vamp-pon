# 157. Multi-Lineage Balance and Visual Rules

This document prevents dual-lineage and triple-lineage characters from becoming cheap power creep.

## Balance rule

Multi-lineage characters are strong, but not freely strong.

They should have at least one of these:

- slow start
- unstable timing
- narrow condition
- self-risk
- relationship cost
- memory cost
- stage dependency
- phase limit

## Ally balance patterns

| Pattern | Meaning |
| --- | --- |
| dual mode | player chooses one side at a time |
| delayed second effect | second lineage triggers after condition |
| risk burst | huge output with recovery cost |
| support plus damage | strong but not pure DPS |
| bond locked | full power needs relationship progress |

## Enemy balance patterns

| Pattern | Meaning |
| --- | --- |
| phase change | lineage changes at HP threshold |
| false tell | wrong memory creates fake attack cue |
| exposed weakness | revealing true lineage weakens enemy |
| unstable overload | boss becomes dangerous, then vulnerable |
| vessel break | destroying vessel part changes behavior |

## Visual hierarchy

Do not show all lineages equally.

Use:

1. primary shape
2. secondary accent
3. hidden reveal mark

Examples:

- fire + water: warm vessel with mist edge, not orange-blue split body
- light + dark: mostly covered light with thin bright rim
- fire + lightning + water: one fused vessel, not three separate props

## UI icon rule

A multi-lineage icon should not be a rainbow badge.

Use:

- one main icon shape
- one small secondary mark
- one hidden marker for late reveal

## Enemy readability rule

Strong enemies can be visually complex, but their attack role must be readable.

At 1x the player should still understand:

- chase
- shoot
- explode
- shield
- summon
- zone control

## Story gate rule

A multi-lineage character needs a story gate.

Before use, answer:

- why two or three lights coexist
- who paid the cost
- what relation this creates
- what Yui once saw but did not understand
- what should remain unrevealed after the first encounter

## Production rule

Do not promote a multi-lineage design unless:

- one primary identity is readable
- secondary identity supports story and gameplay
- cost is documented
- relation pressure is documented
- visual effect does not confuse pickups, UI, or enemy eyes
