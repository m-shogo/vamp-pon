# 参照システム方針

## 結論

Vamp Pon のシステム・仕様は、基本的に **Vampire Survivors ライク**でよい。

無理に独自システムを足して、ゲームの分かりやすさや完成可能性を下げない。

## 基本方針

以下は Vampire Survivors 系の定番構造を踏襲する。

- プレイヤーは基本的に移動操作のみ
- 攻撃は自動発動
- 敵が大量に湧く
- 敵を倒して経験値を拾う
- レベルアップで強化を選ぶ
- 武器やパッシブが強くなる
- 時間経過で敵が強くなる
- 一定時間生存を目指す
- 終盤は敵密度とビルド完成度で押し切る

## まんまでよい部分

### 操作

- 移動中心
- 攻撃ボタン連打は不要
- 片手でも遊べるくらい軽い
- ぼけっと遊べる

### 成長

- 経験値回収
- レベルアップ
- 3択程度の強化選択
- 武器レベルアップ
- パッシブ強化
- 条件を満たすと武器進化

### ゲーム進行

- 時間制
- 序盤はゆるい
- 中盤から敵の種類と密度が増える
- 終盤はビルド不足が露呈する
- ボス/エリート敵で節目を作る

### 気持ちよさ

- 敵が溶ける
- 数字が伸びる
- 武器が派手になる
- 成長が分かりやすい
- もう1回遊びたくなる

## 無理に入れないもの

以前の仮案「5戦線」「前後左右中央の危険エリア」は、現時点では必須システムにしない。

理由:

- ヴァンサバの良さである分かりやすさが薄れる可能性がある
- 実装と調整が重くなる
- まずは王道の気持ちよさを作る方が重要
- 独自性をシステムで無理に作る必要はない

ただし、将来的な追加要素やUI表現として使える可能性は残す。

扱い:

- MVP必須ではない
- 最初のゲーム仕様には入れない
- アイデアバックログ扱い
- 後から必要なら小さく試す

## 差別化する場所

システムでは無理に差別化しない。

差別化は以下で行う。

### 1. デザイン

- キャラクター
- 敵の見た目
- 背景
- 色味
- UIトーン
- 世界観

### 2. テーマ

- かわいい
- ゆるい
- 少し不気味
- 小さい世界
- 収集したくなる雰囲気

### 3. 演出

- 攻撃の気持ちよさ
- 敵撃破の反応
- レベルアップ演出
- 武器進化演出
- リザルトの見せ方

### 4. 遊びやすさ

- 迷わないUI
- 見やすい敵/弾/経験値
- テンポの良い成長
- 短時間でも満足できる

### 5. 制作範囲の絞り方

- 少ない武器で気持ちよくする
- 少ない敵で役割を分ける
- 小さいステージで完成度を上げる

## 注意すること

Vampire Survivors を参考にしてよいが、以下はコピーしない。

- ソースコード
- 素材
- キャラクター
- 武器名
- 敵名
- ステージ名
- UIの完全な見た目
- ロゴ
- 固有の文章や説明文

参照するのは、あくまでゲームジャンルとしての構造と体験。

## MVP方針

MVPは以下でよい。

- 1キャラ
- 1ステージ
- 武器3〜5個
- 敵3〜5種類
- レベルアップ3択
- 経験値回収
- 10分以内の短い生存モード
- 簡単なボス/エリート
- リザルト

前後左右中央などの追加システムは入れない。

## 現時点の優先順位

1. ヴァンサバ系として普通に気持ちいいこと
2. 操作が分かりやすいこと
3. 視認性が高いこと
4. デザイン方向が魅力的なこと
5. 個人開発で完成できること
6. 独自システムを無理に足さないこと
