# Design Timing Decision

## 目的

Vamp Ponで「デザインが先か、実装が先か」を明確にする。

結論:

```txt
本格デザインは先ではない。
ただし、デザインの方向・視認性ルール・画面ワイヤーはPrototype 1前に最低限必要。
```

---

# 1. なぜ本格デザインを先にしないか

Vamp Ponの最初の検証対象は以下。

```txt
移動が気持ちいいか
自動攻撃が気持ちいいか
欠片回収が気持ちいいか
60秒以内にレベルアップして嬉しいか
```

これは、本格キャラ絵や背景がなくても検証できる。

むしろ本格デザインを先に作ると、以下のリスクがある。

```txt
見た目に引っ張られて操作感の問題を見落とす
絵に合わせて仕様を歪める
素材制作に時間を使いすぎる
仮説検証前に完成品気分になる
修正コストが重くなる
```

---

# 2. ただし、完全にデザイン後回しでもない

完全にデザインを後回しにすると、以下が起きる。

```txt
スマホで見づらい
自キャラ/敵/欠片が判別できない
UI配置が後で崩れる
仮素材が雑すぎて評価不能になる
世界観の方向がズレる
```

そのため、先に必要なのは「本格デザイン」ではなく「デザイン設計」。

---

# 3. 先にやるデザイン

Prototype 1前にやってよい。

```txt
画面ワイヤー
UI配置
自キャラ/敵/欠片の識別ルール
仮素材ルール
色の役割だけ決める
文字サイズ基準
視認性チェック
```

## 例

```txt
自キャラ: 常に一番見える
敵: 背景より暗い/輪郭あり
欠片: 小さな光として見える
HP/時間: 常時読める
必殺技ボタン: 右下に置ける余白を残す
```

---

# 4. 先にやらないデザイン

Prototype 1前にやらない。

```txt
完成キャラ立ち絵
完成敵イラスト
完成背景
完成ロゴ
完成アイコン
大量アニメーション
本番UI装飾
ストア用スクショ
```

理由:

```txt
Prototype 1の検証に不要
後で仕様変更に巻き込まれる
```

---

# 5. 推奨順序

## Step 1: Design Guardrail

```txt
視認性ルール
画面ワイヤー
仮素材ルール
UI安全領域
```

## Step 2: Prototype 1

```txt
移動
自動攻撃
欠片回収
初レベルアップ
```

## Step 3: Playtest

```txt
スマホで見えるか
操作できるか
欠片が気持ちいいか
```

## Step 4: Prototype 2/3

```txt
武器差
3択
カプセル
進化
必殺技
```

## Step 5: Full Design

```txt
キャラ造形
背景美術
UIデザイン
演出
ロゴ
```

---

# 6. 具体的な判断

## 今やるべきデザイン作業

```txt
Prototype 1用ワイヤーフレーム
仮素材の視認性ルール
スマホUI安全領域
最小カラーロール
```

## 今やらないデザイン作業

```txt
本番キャラ絵
本番背景
本番UI
ロゴ
アイコン
```

---

# 7. 最終判断

```txt
Design Direction: YES, before Prototype 1
Full Visual Design: NO, after Prototype 3 validation
```

Vamp Ponでは、デザインを軽視しない。

ただし、最初に必要なのは完成絵ではなく、スマホで遊べるための視認性設計。

## 一言で言うと

```txt
デザインの設計は先。
絵の作り込みは後。
```
