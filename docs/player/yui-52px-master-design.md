# ユイ 52px Master 設計書

この文書は、ユイを「Vamp Pon の顔として長く愛されるIPキャラ」にするための **52px master** 設計を固定するもの。

これは sprite ではなく設計書。
この文書だけで sprite を完成扱いにしないこと。
実素材は Aseprite GUI 手仕上げを経て、`docs/reviews/yui-next-production-readiness-plan.md` のゲートを通ってから production に入る。

## 1. ユイのIP核

ユイは「夜の中で小さく光る子」。
以下は、どのサイズ・向き・ポーズでも崩してはいけない固定アイデンティティ。

| 要素 | 内容 | 崩してはいけない理由 |
| --- | --- | --- |
| 大きな丸い青フード | 頭をやさしく包む丸いフード | シルエットの主役。最初にユイと認識させる記号 |
| 茶赤の前髪 | フードの下からのぞく束感のある前髪 | 青フードとの色対比で「人」だと分かる |
| 大きめで可愛い目 | 顔の中で大きく、丸く、優しい目 | 愛嬌の中心。グッズ化の生命線 |
| 白いキャッチライト | 目の中の小さな白い光 | 「生きている」「光を見ている」印象 |
| ほんのり頬 | 薄いピンクの頬 | 体温・幼さ・優しさ |
| 古紙色の服 | 生成り〜古紙色のワンピース＋エプロン | 「記憶／紙」の世界観。青フードを受ける明色 |
| 小さな脚と靴 | 裾の下にのぞく脚と暗色のブーツ | 「立っている子」だと分かる。三角形化の防止 |
| 右手のランタン | 右手側に下げた小さなランタン | 第二の主役記号。輪郭にリズムを作る |
| ランタンの中の小さな記憶の光 | 暖色コア＋小さなスパーク | ゲームテーマ「記憶の光」を体現 |
| 少し不安だけど優しい表情 | 眉はわずかに困り、口は小さく柔らか | 物語性。無表情マスコットにしない |
| 夜の中で小さく光る子 | 暗背景で沈まず、ランタンの暖色が灯る | ゲーム画面・グッズ両方の世界観 |

> このどれか1つでも欠けると「ユイ」ではなくなる。
> 特に **青フード / 茶赤前髪 / 大きな目 / 右手ランタン** の4点は最優先。

## 2. 52px master の目的

42px master（既存 production）では、以下を同時に成立させる解像度が足りなかった。
その結果が c10e6c0 の「青いキノコ」化（フードが顔と体を潰す）。

52px master は、これらを解決するための **基準解像度** とする。

| 42pxで弱かった点 | 52pxでの解決方針 |
| --- | --- |
| 顔の可愛さ | 顔を 20〜25% 確保し、目・頬・口・眉を別ピクセルで描き分ける |
| 前髪の束感 | フチに strand tip を数本、束の明暗を2〜3階調で入れる余地を作る |
| フードの丸み | 外周＋内側ライニング影＋上左ハイライトの3層を置ける幅を取る |
| 服の厚み | 襟・エプロン・折り線・裾・しおり紐を別要素として置ける |
| ランタンの魅力 | ケージ枠・暖色2階調・記憶の光スパークを分離して描ける |
| シルエットの記憶性 | フード/顔/体/ランタンの比率を固定し、黒塗りでも判別可能にする |
| グッズ展開への耐性 | アクキー/ステッカー/ぬいぐるみ/スタンプで「欲しい」と思える密度 |

> 52px は「master（原型）」であり、必ずしも gameplay 表示サイズではない。
> gameplay 用サイズへの落とし込みは §6 で扱う。

## 3. 比率設計

縦52pxを基準に、要素の縦方向占有比を以下に仮定する。
（横ではなく縦比率を基準にするのは、立ち姿の主人公は縦のシルエットで認識されるため。）

| 要素 | 縦比率 | 52px換算の目安 | 根拠 |
| --- | --- | --- | --- |
| フード | 40〜45% | 約 21〜23px（上端〜フード下縁） | シルエットの主役。最初の認識記号なので最大面積を与える。ただし顔を潰さない上限が45% |
| 顔 | 20〜25% | 約 10〜13px | グッズの生命線。これ未満だと目が点になり拡大で可愛くない。フードと重なる帯で確保 |
| 体 | 25〜30% | 約 13〜16px | 「立っている子」を成立させる。脚と靴を含む。これ未満だと三角形化する |
| ランタン | 8〜12% | 約 4〜6px（縦） | 第二記号。大きすぎると主役を食い、小さすぎると記号として読めない |

設計上の重なりルール:

- フードと顔は **重なる**（フードが顔を「囲む」）。フード40〜45%・顔20〜25%は排他ではなく、顔はフード開口の内側に置く。
- 顔の中心はキャンバス中央よりやや上（フードに抱かれる位置）。
- ランタンは右側に逃がし、中央 `hitCore` 帯と縦で重ねない（prop 誤認防止）。
- 脚・靴は体の最下部に必ず見せる（三角形化の防止線）。

なぜこの比率か:

1. フードを最大記号にしつつ、45%上限で「キノコ化」を構造的に禁止する。
2. 顔20〜25%を死守することで、1xでも目が読め、拡大で可愛い。
3. 体25〜30%＋脚靴で「主人公が立っている」シルエットを保証する。
4. ランタン8〜12%で輪郭にリズムを作り、IPの第二記号を成立させる。

## 4. 色設計（Vamp Pon palette: Yui固定色）

ユイは以下の固定色ファミリーで描く。
他素材（敵・背景・UI）と衝突しないよう、明色（cream）と暖色（amber）はユイ側の主張を保ちつつ、背景の暖色灯りより前に出す。

| 役割 | 名前 | 参考RGB（master基準・GUIで微調整可） | 用途 |
| --- | --- | --- | --- |
| Yui blue | フード基調 | dark `#2E3C68` / mid `#425C8E` / light `#627EB2` / spec `#8EA8D6` | フードの3〜4階調。暗背景で沈まない明度を確保 |
| old-paper cream | 服基調 | base `#E0CEA2` / shadow `#BEA87E` / hi `#F4E6C2` / apron `#ECDEBA` | ワンピース・エプロン・襟 |
| memory amber | ランタンの光 | warm `#FAC45C` / mid `#FFE896` / core `#FFFCE0` / spark `#FFF6EC` | ランタンの暖色コア＝記憶の光 |
| brown-red hair | 前髪 | dark `#4A2620` / mid `#743E2E` / hi `#A8664C` | 青フードとの対比で「人」を成立させる |
| soft cheek pink | 頬 | `#EC9C90` | ほんのり頬・体温 |
| ink-safe outline | 輪郭 | `#1E182A`（純黒は使わない暗紫） | 敵の黒インクと差別化する outline。純黒NG |

色の禁止:

- 純黒（`#000000`）の outline は使わない（敵の黒インクと混ざる）。`ink-safe outline` を使う。
- ランタンの amber を背景の暖色灯りと同明度にしない（pickup/背景と競合する）。
- フードの blue を暗背景と同明度にしない（沈む）。

## 5. NG例（これをやったら作り直し）

c10e6c0 を含む過去の失敗を構造的に禁止する。

| NG | 何が起きるか | 防ぎ方 |
| --- | --- | --- |
| 青いキノコ化 | フードが顔と体を潰し、頭でっかちの塊になる | フード上限45%・顔20〜25%死守・体25〜30%死守 |
| フードが顔を潰す | 顔が小さくなり目が読めない | 顔はフード開口の内側に20〜25%で確保 |
| ランタンが浮く | 腕・手とつながらず別オブジェクトに見える | 右腕→手→取っ手→ケージを必ずつなぐ |
| 服が三角形になる | 脚・靴がなく、のっぺりした円錐 | 裾の下に脚と靴を必ず見せる |
| 目が点で終わる | 愛嬌が消え、グッズに耐えない | 目は複数ピクセル＋虹彩＋白キャッチライト |
| scriptの楕円に見える | 楕円・矩形の塗りつぶしのまま、手の跡がない | GUIで束・折り・陰影を1px調整（§handoff参照） |
| 1xでは読めるが拡大で可愛くない | グッズ化で破綻する | 1xと4x/6xの両方で都度確認 |
| temporary/draftをproduction化 | c10e6c0 の再発 | readiness-plan のゲート未達は production禁止 |

## 6. master と gameplay 表示サイズの役割整理

「52pxで master を作る」ことと「ゲーム内で何pxで表示するか」は分けて考える。

| サイズ | 役割 | 備考 |
| --- | --- | --- |
| **52px** | **master / IP原型** | 顔・前髪・服・ランタンを最も豊かに描ける基準。グッズ・設定画・turnaround の原型。今回の設計対象 |
| 48px | 中間表示候補 | 52px master を素直に縮小しやすい中間。gameplay とグッズの折衷案 |
| 42px | 現 gameplay 表示（既存 production） | 既存 manifest / collision 前提。gameplay定数（radius / visualSize 等）はこのサイズ運用に紐づく |

役割整理の原則:

1. **デザインは 52px master で決める。** 可愛さ・記号性・比率は master で確定する。
2. **gameplay 反映は別判断。** 52px をそのまま使うか、48px / 42px へ落とすかは、collision・視認性・他素材との整合で決める。
3. **gameplay定数は今回触らない。** master 設計はあくまで見た目の原型。`radius` / `visualSize` / `hitCore` 等は別タスク。
4. 縮小する場合も「AI/script縮小だけで完成扱いしない」。各サイズで 1x 確認と必要な手直しを行う。

> 推奨フロー: 52px master を GUI で仕上げ → readiness ゲート通過 → その後に「どの表示サイズで gameplay 反映するか」を別途決定。

## 7. この設計書の使い方

1. この設計書で IP核・比率・色・NGを頭に入れる。
2. [yui-aseprite-gui-handoff.md](yui-aseprite-gui-handoff.md) の手順で Aseprite GUI で 52px master を手仕上げする。
3. [yui-merchandise-character-checklist.md](yui-merchandise-character-checklist.md) で IP/グッズ観点を採点する。
4. [../reviews/yui-next-production-readiness-plan.md](../reviews/yui-next-production-readiness-plan.md) のゲートを全て満たすまで production に入れない。
