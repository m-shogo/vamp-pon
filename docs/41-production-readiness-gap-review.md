# 制作前仕様の到達度レビュー

## 目的

Vamp Pon の仕様はかなり増えたが、ゲーム会社が制作に入る資料として十分かをレビューする。

結論から言うと、**まだ全部は揃っていない**。

企画・世界観・MVP仕様・非デザイン開発方針はかなり進んだ。

しかし、制作会社やゲームチームがそのまま作れるレベルには、まだ以下が不足している。

```txt
ゲームコンセプトの1枚化
プレイヤー体験の明文化
コアループ図
画面遷移図
入力仕様
スマホUX仕様
バランス基準
プロトタイプ検証項目
デザインブリーフ
サウンド方針
アクセシビリティ
開発マイルストーン
リスク管理
削る仕様リスト
```

## 現時点で揃っているもの

### 1. ゲームの基本方向

```txt
ヴァンサバ系
移動中心
自動攻撃
経験値/欠片回収
レベルアップ選択
武器進化
時間制サバイバル
```

### 2. Vamp Pon独自要素

```txt
記憶の欠片
黒インク
記憶カプセル
忘れ物/地図帳/旅の記録
裏ストーリー断片
キャラ別必殺技
```

### 3. MVP仕様

```txt
キャラ: ユイ / ミチル
武器: 5種
パッシブ: 5種
敵: 5種 + 強敵
進化: 2種
記憶カプセル
リザルト
図鑑/実績文言
```

### 4. 技術方針

```txt
Vite + TypeScript + Phaser
Webベース
スマホブラウザ検証
PWA/Capacitorへ逃げ道
```

### 5. 破綻防止方針

```txt
データ駆動
デザインとロジック分離
スマホ前提
仮素材でロジック検証
テスト可能な純粋関数
調整ログ
```

## まだ足りないもの

## 1. ワンシート企画書

ゲーム会社が最初に見るなら、まず1枚で分かる資料が必要。

必要項目:

```txt
タイトル
ジャンル
対応プラットフォーム
想定プレイ時間
ターゲット
一言コンセプト
コアループ
独自性
遊びの快感
MVP範囲
やらないこと
```

目的:

```txt
このゲームは何かを即理解する
```

## 2. プレイヤー体験の定義

仕様が増えるほど、体験がぶれる。

必要な定義:

```txt
最初の30秒で何を感じるか
1分で何が起きるか
3分で何を理解するか
5分で何を迷うか
8分で何が盛り上がるか
リザルトで何を思うか
もう一度遊ぶ理由は何か
```

## 3. コアループ図

文章だけではなく、循環構造が必要。

```txt
移動する
↓
影を払う
↓
欠片を拾う
↓
レベルアップする
↓
武器/パッシブを選ぶ
↓
強くなる
↓
強敵を倒す
↓
記憶カプセルを開ける
↓
進化/報酬
↓
朝まで残る
↓
リザルト/実績/図鑑
↓
永続強化
↓
もう一度
```

## 4. 画面遷移図

デザインではなく、機能遷移として必要。

```txt
起動
↓
タイトル
↓
キャラ選択
↓
ステージ開始
↓
プレイ
  ├ レベルアップ
  ├ 記憶カプセル
  ├ ポーズ
  └ 終了
↓
リザルト
↓
強化 / 図鑑 / もう一度
```

## 5. スマホ入力仕様

アプリゲーム前提なので、ここは重要。

必要項目:

```txt
縦持ち基準
仮想スティック位置
必殺技ボタン
自動発動設定
レベルアップカードのタップ仕様
ポーズ導線
中断/復帰
```

## 6. バランス基準表

数値はあるが、判断基準がまだ弱い。

必要項目:

```txt
初回Lv2到達目標
3分カプセル到達率
5分死亡率
8分クリア率
進化到達率
必殺技使用回数
敵撃破数
フレームレート
```

## 7. 検証プロトタイプ計画

実装前に「何を確認するために作るか」を決める。

```txt
Prototype 1: 1分操作感
Prototype 2: 3分成長感
Prototype 3: 8分MVP
Prototype 4: スマホ実機検証
```

各プロトタイプに合格/不合格基準が必要。

## 8. デザインブリーフ

デザインは保留だが、デザイナーに渡すためのブリーフは必要。

まだ決めない項目:

```txt
色
フォント
キャラ見た目
背景美術
```

決めてよい項目:

```txt
縦持ち
読みやすさ優先
影と欠片の視認性
文字は少なめ
裏ストーリーは説明しすぎない
仮素材で完成度評価しない
```

## 9. サウンド方針

ゲーム会社レベルならサウンドも必要。

最低限必要:

```txt
欠片取得音
レベルアップ音
カプセル開封音
進化音
必殺技音
被弾音
クリア音
失敗音
```

まだ作曲方針までは不要。

## 10. アクセシビリティ

スマホゲームとして必要。

```txt
文字サイズ
色だけに依存しない情報表示
画面揺れON/OFF
ダメージ数字ON/OFF
自動必殺技ON/OFF
片手操作への配慮
```

## 11. リスク管理

仕様が増えすぎると失敗する。

主なリスク:

```txt
見た目が決まらず実装評価できない
裏ストーリーが増えすぎる
必殺技が強すぎる
スマホで敵数が重い
8分でも長い
レベルアップ文言が読みにくい
仮素材でテンションが下がる
```

## 12. 仕様凍結ライン

MVPに入れる/入れないを凍結する必要がある。

MVP必須:

```txt
ユイ
夜の鉛筆
インクの影
欠片
レベルアップ3択
武器5種
パッシブ5種
敵5種
記憶カプセル
進化1〜2種
リザルト
```

MVP後:

```txt
ミチル
永続強化の完全版
詳細図鑑
黒インク床
10分モード
演出分岐
PWA/Capacitor
```

## 結論

仕様はかなり揃っている。

しかし、**まだ制作に入るには早い**。

今やるべきは、実装ではなく以下。

```txt
1. ワンシート企画書
2. コアループ図
3. プレイヤー体験タイムライン
4. 画面遷移図
5. スマホ入力仕様
6. プロトタイプ検証計画
7. 桜井政博さんの設計思想を参考にしたチェックリスト
8. MVP凍結リスト
```

この8つを作れば、制作前資料としてかなり強くなる。
