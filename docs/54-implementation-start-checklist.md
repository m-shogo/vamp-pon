# 実装開始チェックリスト

## 目的

Vamp Pon を実装に入る前に、必要な資料・判断・スコープ・技術準備が揃っているか確認する。

このチェックリストを満たさずに実装を広げると、手戻りが増える。

---

# 1. 企画/仕様チェック

```txt
[ ] ワンシート企画書がある
[ ] コアループがある
[ ] 8分体験タイムラインがある
[ ] MVP凍結リストがある
[ ] スマホ入力仕様がある
[ ] プロトタイプ検証計画がある
[ ] リスク管理表がある
[ ] GDDインデックスがある
```

## 合格条件

```txt
ユイで8分遊んで何を検証するのか説明できる。
```

---

# 2. スコープチェック

## MVP必須だけに絞れているか

```txt
[ ] ユイだけで開始できる
[ ] 8分ステージだけで開始できる
[ ] 武器5種以上に増やしていない
[ ] パッシブ5種以上に増やしていない
[ ] 敵5種+強敵以上に増やしていない
[ ] 2ステージ目を作らない
[ ] ミチルを先に作らない
[ ] 本格デザインを先に作らない
```

## 合格条件

```txt
Prototype 1〜3に必要なものだけを実装できる。
```

---

# 3. 技術チェック

```txt
[ ] Vite + TypeScript + Phaser で進める判断がある
[ ] pnpm を使う
[ ] TypeScript strict を使う
[ ] Vitest を入れる
[ ] localStorage保存方針がある
[ ] スマホブラウザ検証を前提にする
```

## 合格条件

```txt
pnpm dev でブラウザ起動できる構成にする。
```

---

# 4. データ駆動チェック

```txt
[ ] 武器データがコード直書き分岐にならない
[ ] 敵データがコード直書き分岐にならない
[ ] パッシブがデータで管理される
[ ] ウェーブがデータで管理される
[ ] 進化条件がデータで管理される
[ ] 実績/図鑑もデータで管理できる
```

## 禁止

```ts
if (weapon.name === '夜の鉛筆') {
  // 固有処理
}
```

## 推奨

```ts
switch (effect.type) {
  case 'projectile':
    // projectile共通処理
}
```

---

# 5. スマホ操作チェック

```txt
[ ] 縦持ち390x844基準
[ ] 仮想スティック
[ ] 必殺技1ボタン
[ ] 3択カードタップ
[ ] 非アクティブ時ポーズ
[ ] PCキーボードだけで満足しない
```

## 合格条件

Prototype 1からスマホブラウザで確認する。

---

# 6. デバッグチェック

```txt
[ ] F1 debug overlay
[ ] F2 force level up
[ ] F3 spawn capsule
[ ] F4 fill ultimate
[ ] F5 skip +60 sec
[ ] F6 clear enemies
[ ] F7 heal player
[ ] /?debug=true のスマホデバッグメニュー方針
```

## 合格条件

10分/8分を毎回通しプレイしなくても検証できる。

---

# 7. テストチェック

最初から全部は不要。

ただし、以下の純粋関数はテスト可能にする。

```txt
[ ] LevelUpSystem
[ ] EvolutionSystem
[ ] WaveSystem
[ ] SaveSystem
[ ] XPカーブ
```

## 合格条件

Phaserに依存しないロジックを `systems` または `domain` に分離する。

---

# 8. アクセシビリティ/UXチェック

```txt
[ ] 音なしでも分かる
[ ] 画面揺れOFFを想定
[ ] ダメージ数字OFFを想定
[ ] 自動必殺技設定を想定
[ ] 文字がスマホで読める
[ ] 色だけで判断させない
```

---

# 9. サウンド/素材チェック

MVP初期は仮でよい。

ただし、素材を使うなら記録する。

```txt
[ ] 素材ライセンスログを作る
[ ] フリー素材のライセンスを記録する
[ ] AI生成素材の生成元/利用条件を記録する
[ ] 仮素材と本素材を分ける
```

---

# 10. 実装開始の合格ライン

以下を満たしたら、Prototype 1 実装に入ってよい。

```txt
[ ] MVP凍結リストがある
[ ] Prototype 1の目的が明確
[ ] デザインは仮素材で進めると合意済み
[ ] 仮素材で完成度評価しない
[ ] スマホ縦持ちで確認する
[ ] データ駆動で作る
[ ] 最初は1分遊べる核だけ作る
```

## 実装を止めるべき状態

```txt
MVP前にキャラ追加したくなった
見た目が気になってロジック検証が止まる
8分MVP前にアプリ化したくなった
武器を増やす話になった
ストーリー演出を増やしたくなった
```

この場合は実装を止めて、MVP凍結リストに戻る。

---

# 最終判断

Prototype 1の実装に入るなら、目的はこれだけ。

```txt
スマホ縦持ちで、移動・自動攻撃・欠片回収・初レベルアップが気持ちいいか。
```

これ以外は入れない。
