# 1. 二層の名前

## 共通システム名

**黒耀化（こくようか）**

全キャラ共通のゲームシステム / UI / ルール名。

- `黒曜化` は使わない
- 暴走 / バーサーク / 闇落ちとは呼ばない
- 黒いのに耀く、怖いが完全な悪ではない状態

## キャラ固有呼称

各人物は同じ現象を、自分の象徴に引き寄せた別名で呼ぶ。

UIのシステム見出しは `黒耀化` のままでもよい。
キャラ詳細、カットイン副表示、灯し手の記録、会話では固有呼称を使える。

```txt
黒耀化
└ キャラ固有呼称
   └ 既存の黒耀化副題 / short copy / distorted trait
```

固有呼称を持たせる狙い:

- 全員が同じ黒い強化に見えない
- その人の長所と弱さが一目で分かる
- キャラを使い込む理由になる
- 灯録で比較して読む楽しさが出る

# 2. 黒耀化の意味

黒耀化は、本人の長所・願い・守り方が黒インクによって**過剰化**した状態。

```txt
長所
↓
守りたい気持ち
↓
限界を越えて過剰化
↓
強いが危うい力になる
```

完全な別人格にはしない。
本人の意識は残る。

強くなる理由は、通常では触れられない深い記憶 / 影 / 黒インク層へ一時的にアクセスできるから。

反動は `煤返り`。

# 5. Gameplay value

黒耀化は物語演出だけではない。
ヴァンサバ系のプレイ中に「危険だが強い」明確なビルド判断になる。

設計方向:

- 通常ビルドではできない強い特性変化
- キャラ固有の強化方向
- 使用タイミングを考える価値
- 煤返りによる短期 / run内コスト
- 一部の夜明け星図条件で「黒耀化あり / なし」の別攻略
- Bond / Supportで反動軽減や救援の違いを出せる余地

禁止:

- ただ攻撃力が上がるだけ
- 全員同じ効果
- 使い得
- 使用そのものを悪扱い
- permanent deathの直接原因にする

# 6. 灯録での情報量

`灯し手の記録` では、好きな人が深く読めるよう黒耀化情報を多めに持ってよい。

段階例:

```txt
初使用
→ 固有呼称 / 短い説明

複数回使用
→ 歪む長所 / 星獣反応

Bond / 特定達成
→ 煤返り後の日常会

高難度 / 特殊条件
→ その人がなぜその形に歪むのか

朝側の進行
→ 成長後の対比
```

読まないプレイヤーは、

- 効果
- cooldown / cost
- 強化値
- 新しいtrait

だけ理解できれば遊べる。

情報を読むことを強化条件にはしない。

# 7. 旧資料から吸収したもの

吸収済み:

- 共通名 `黒耀化`
- ユイ専用 `黒灯化`
- 「共通名 + キャラ固有呼称」の二層構造
- `黒 + キャラ象徴 + 化` を基本とする命名思想
- 闇落ちではなく長所 / 願いの過剰化
- 強いが反動がある
- 星獣が本人の危うさへ反応する
- 黒耀化後の日常に痕跡が残る
- 朝側の成長と対比する

捨てた / 再設計したもの:

- 過去ロスターに紐づく固有名
- 現Current 21と矛盾する星獣
- 古いキャラモチーフ
- `黒耀ゲージ` という旧UI名（Currentは `黒耀瓶`）

Runtime dataの `kokuyouForms.ts` は現時点で変更しない。
固有呼称をruntimeへ出す時は専用data-sync commitで行う。
