# ヨルノシルベ — 灯紋 In-world Behavior Contract v1

Date: 2026-08-10  
Status: **CURRENT CHARACTER / VISUAL SYSTEM BEHAVIOR — ORIGIN MYSTERY REMAINS OPEN**

> 灯紋はCharacterの「属性」「階級」「血統」「性格診断結果」ではない。
> Nightで繰り返された**選び方の軌跡**が、灯紋具などを通して読める形になったもの。
>
> この文書は灯紋の作中挙動を固定するが、「誰が最初に灯紋を発見したか」「Nightがなぜ形を返すのか」まではSeries Mysteryとして残す。

---

# 1. 一文定義

```txt
灯紋
= Nightの中で何度も現れた「その人らしい選び方」が
  一つの答えへ固定されず、線・点・余白として観測された痕跡
```

重要なのは**人格そのものではない**こと。

同じ人でも:

- 環境
- 関係
- 学習
- 朝を迎えた後の選択

によって「線の使い方」は変わり得る。

しかしCharacter identityを商品都合で毎回描き換えないため、Current title内では**base Toumon geometryをstable visual identityとして扱う**。

---

# 2. 灯紋はPower Sourceではない

灯紋があるから強い、ではない。

```txt
灯紋 ≠ mana
灯紋 ≠ level
灯紋 ≠ rank
灯紋 ≠ class
灯紋 ≠ chosen-one certificate
```

### Game presentation

灯紋がUIで:

- unlock
- art
- collection
- relationship
- phase

へ使われても、世界設定上「灯紋の大きさ = 戦闘力」にはしない。

### Commercial guard

Rare / limited merchandiseだからCharacterの灯紋を豪華化して「上位紋章」にしない。

---

# 3. 灯紋具は「読む」道具

灯紋具は灯紋を与える装置ではない。

**観測 / 記録 / 再表示を助ける道具。**

```txt
人物の選択
↓
Nightに痕跡
↓
灯紋具が読める範囲を抽出
↓
線として表示
```

## できる

- Current base Toumonを表示する
- 無紋 / 通常 / 暁 / 黒紋の差を表示する
- reciprocal conditionを満たした双灯紋を一時表示する
- 記録へToumon identityを紐付ける

## できない

- 人の心を読む
- 嘘を判定する
- 恋愛感情を判定する
- 性的指向 / gender identityを判定する
- 血縁を判定する
- 犯罪者 / 善人を分類する
- 未来を予言する
- traumaの内容を暴く
- sealed memoryの中身を勝手に開く

**灯紋はprivacy bypass deviceにしない。**

---

# 4. 無紋

無紋は「未熟」「弱い」「価値がない」ではない。

Meaning:

- まだ観測条件が揃っていない
- Night内で一貫した痕跡として読めない
- 本人の選択が少なすぎる
- 記録側が不足している

のいずれか。

### 禁止

- 無紋者差別社会をdefault loreにしない
- 無紋 = 一般人、灯紋 = 選ばれし者、にしない
- 生まれつきの紋章階級制度へしない

---

# 5. 通常灯紋が読める条件

人物が「一度だけすごい決断」をしたから現れるのではない。

少なくともNarrative上:

```txt
A. 同じ価値観が別の状況で2回以上現れる
B. ただの口癖ではなく、実際のchoice/actionになる
C. 誰か/何かへの関わり方に残る
D. 一つの正解へ閉じず、まだgapを持つ
```

を満たした時に、灯紋具がstable formを読める。

### Consequence

Character intro時点で既に灯紋がある人物もいてよい。
物語中に初めて読める人物もいてよい。

全員が同じchapterで一斉unlockしなくてよい。

---

# 6. Gapの世界設定上の意味

全灯紋に最低1つintentional gapがある。

これは単なるlogo ruleではない。

```txt
gap
= Nightが「その人はまだ選び直せる」と読んだ場所
```

ただしNightを人格あるjudgeとして断定しない。

Character側からは:

- 未完
- 保留
- 他者の余地
- 戻り道
- 手放せる場所

として読める。

### Black Inkとの接続

Black Ink = semantic fixation。

だから黒紋では、Characterごとの「固定しすぎる危険」が**gapを塞ぐ / nodeを囲う / lineを唯一化する**方向に出る。

この接続により黒紋を単なるevil skinにしない。

---

# 7. 暁紋

暁紋はPower-up medalではない。

```txt
base Toumon
+ 一つだけ選び直した証拠
= 暁紋
```

### Rule

- geometry changeは1操作
- base identityは残る
- 「欠点が消えて完璧」にはしない
- Characterのbody / age / disability / presentationを改善表現にしない

### Examples of semantic operation

- close → open
- inward → outward
- stop → continue
- protect → leave exit
- hold → reveal edge
- measure → leave unmeasured point

---

# 8. 黒紋

黒紋は別人格の印ではない。

```txt
そのCharacterの長所
+ fear / urgency
+ 「この方法しかない」
→ same geometryの1箇所が過剰になる
```

### Examples

- 守る → 囲いすぎる
- 返す → 相手の意思より返却を優先
- 測る → 測れないものを切り捨てる
- 保存 → 閉じ込める
- 預かる → 本人が開ける余地を消す

### Visual contract

- 80%以上baseと同じ
- demon horn / thorn / skull / evil eye等を足さない
- Character Theme HEXを真っ赤/黒へ単純置換しない

---

# 9. 双灯紋

双灯紋は**相性診断ではない**。

出現条件は「二人が仲が良い」でも「恋愛関係」でもない。

最低限:

```txt
A. 互いのchoiceを一度以上見ている
B. 相手の選択を奪わず、自分も選んでいる
C. 同じ場面で一つのshared action / handoffを成立させる
```

時に一時的に読める。

### 重要

- enemy / rival関係でも成立し得る
- siblingsでも成立
- buddyでも成立
- mentor / studentでも成立
- romanceでも成立し得るが恋愛証明ではない

### Geometry

- shared node OR shared gap = 1
- original forms remain readable
- heart shapeへ自動変形しない
- 完全fusion logoにしない

---

# 10. 他人からどう見えるか

Default:

- 灯紋具などの観測media上では他者も読める
- 身体へ常時浮かぶtattooではない
- 本人の服や皮膚へ勝手に焼き付かない
- Named Objectへ自然発生する刻印とはLOCKしない

### Optional presentation

強いNight sceneでは:

- 水面
- 窓
- 紙
- 灯りの影
- 一瞬の残光

へ同geometryが反射的に見える演出は可能。

ただし常時魔法HUDのように空中浮遊させない。

---

# 11. 履歴刻との違い

**灯紋** = Character identity mark。

**履歴刻** = Named ObjectのCurrent historyへ、誰がどう関わったかを記録する小印。

履歴刻はToumonをそのまま刻む場合もあるが:

- physical objectに元からあったとは限らない
- shop merchandiseの刻印とCanon objectの刻印を混同しない
- owner / lineageを勝手に増やさない

Replica商品では必ず:

```txt
CANON OBJECT
vs
MERCH REPLICA MARKING
```

をproduction notesで区別する。

---

# 12. Era / history compatibility

Nightでは異なる時代の人物が会える。

だから灯紋デザインを:

- smartphone UI由来
- 現代企業logo由来
- 特定時代の家紋制度由来

にしない。

Simple line geometryなら、古い紙・金属刻印・現代UIのどちらでも同じ形として読める。

### In-world naming

全時代の人物が最初から「灯紋」という共通用語を知っているとは限らない。

Title1のpresentationではplayer-facing共通語を `灯紋` に統一してよいが、古い時代のCharacterが別の俗称を使う余地は残す。

**俗称を増やす時はsystem label競合を起こさない。**

---

# 13. Series 2 / 3 integrity

続編で新Characterを追加する場合:

- 新Toumonは同じprimitive grammarを使う
- Current21のgeometryをretroactively変更しない
- sequel villainだから黒紋だけのCharacter、をdefaultにしない
- old Characterの暁紋をresetしない
- old Characterが不在でもToumon消滅扱いにしない

### New cast admission

新ToumonはCurrent21の:

- dominant family
- node count
- gap orientation
- signature asymmetry

と比較し、最低2軸で十分な差を持つ。

---

# 14. Merchandise behavior

灯紋がgoodsで強い理由を、作中設定と分離しない。

### Player/fan interpretation

Character portraitを使わなくても:

- 「この線はユイ」
- 「このgapはクロオリ」
- 「このstitchはトモリ / ツムギで意味が違う」

と読める状態を目標にする。

### Goods do NOT become canon evidence

- jewelry placement
- clothing location
- package pairing
- limited color

はStory Canonを変更しない。

Character同士の灯紋を同じ商品へ置いたからといって、作中で双灯紋成立済みとは限らない。

---

**「設定を埋めるため」だけに説明しない。**
