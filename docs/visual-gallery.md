# Visual Gallery（ビジュアル確認シーン）

実機で遊ばなくても「戦闘中にどう見えるか」を確認するための開発用シーン。
ゲーム本編には影響しない（URLで起動シーンを切り替えるだけ）。

---

## 起動方法

```sh
pnpm dev
```

ブラウザで以下のURLを開く（`localhost:5173`）。

| URL | 開くページ |
|---|---|
| `/?scene=visual-gallery` | ギャラリー（1ページ目から） |
| `/?scene=combat-mock` | 戦闘モック（5ページ目）に直行 |
| `/?scene=evolution-showcase` | 進化・合体・覚醒（4ページ目）に直行 |
| `/`（無指定） | 通常のゲーム |

`?debug=visual-gallery` などでも可。

### ページ移動

```txt
画面下の ◀ ▶ ボタン / キーボードの左右矢印
```

ページ構成:

```txt
1/5 背景・ユイ・敵     背景、ユイ、敵6種（白目・モチーフ）
2/5 拾得物・UI         欠片/回復/カプセル + 実HUD + レベルアップカード(レア度3種)
3/5 通常武器           基本武器8種の弾サンプル
4/5 進化・合体・覚醒   3種別の比較 + 各「演出を見る」ボタン
5/5 戦闘モック         全部一緒に置いて視認性を確認
```

## 各ページで見るべきもの

### 1. 背景・ユイ・敵
- 背景が紙質の夜（グリッドでない）か。プレイ領域が暗すぎないか。
- ユイがフード＋ランタンの小さな主人公に見えるか。
- 敵6種のシルエットが見分けられるか。白目が見えるか。

### 2. 拾得物・UI
- 欠片＝金の光 / 回復＝包帯紙（緑十字でない）/ カプセル＝コルク瓶に見えるか。
- HUDが情報過多でないか、紙/木の枠に見えるか。
- カードのレア度（★ふつう / ★★良い / ★★★大当たり）が紙質・縁で分かるか。

### 3. 通常武器
- 各武器が「意味」で区別できるか（鉛筆/ガラス玉/しおり/インク染み/星/紙刃/紙ひこうき/街灯の輪）。
- ビーム・ネオン・ギラ星になっていないか。

### 4. 進化・合体・覚醒
- 強化進化が控えめで元武器の延長に見えるか。
- 合体が2モチーフ（インク＋街灯＝夜明けの輪）に見えるか。
- 覚醒ごとにレアアイテムのモチーフ（名前札/レンズ/封筒/風）が分かるか。
- 「演出を見る」で、強化/合体/覚醒の演出差が伝わるか（魔法陣でないか）。

### 5. 戦闘モック
- 背景に敵が埋もれないか。弾が見えるか。
- インク範囲と敵が混ざらないか。拾得物が分かるか。
- HUDが邪魔でないか。スマホ縦で情報量が多すぎないか。

## NG判断基準（見つけたら直す）

```txt
ネオンっぽい光 / 魔法陣 / SFビーム / ギラ星 / 汎用ソシャゲ演出
ただの丸・線・星だけの仮表示
背景や敵と混ざって見えない黒
回復が回復に見えない
合体と覚醒が同じに見える
弾が背景に埋もれる / 敵の目が見えない
ラベルが読めない
```

## スマホ確認時のチェック項目

```txt
390x844相当で各ページが収まるか
◀ ▶ がタップしやすいか
戦闘モックで情報が詰まりすぎていないか
小さい弾/欠片がスマホでも見えるか
カードの文字が読めるか
```

## スクリーンショットについて

Playwright等の自動スクショは導入していない（依存とCIコストが見合わないため）。
確認はブラウザ（または Claude のプレビュー）で上記URLを開いて行う。
将来 reports/ に自動保存したくなったら、Playwright を devDependency に追加して
`pnpm visual:snapshots` を作る方針（今は手動URLで足りる）。

実装の見た目棚卸しは [visual-audit-current.md](visual-audit-current.md)、
レビュー用チェックリストは [visual-next-review-checklist.md](visual-next-review-checklist.md)。
