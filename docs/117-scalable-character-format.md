# Scalable Character Format

## 目的

Vamp Ponを、将来20人プレイアブルキャラになっても破綻しない構造にする。

キャラを増やす目的は、数を増やすことではない。

```txt
遊び方が変わる
関係性が広がる
記憶の見え方が変わる
別テーマや続編にも転用できる
```

この4つを満たすためにキャラクターを設計する。

---

# 1. キャラ設計の基本式

各キャラは、以下の8要素で作る。

```txt
1. 役割
2. 感情の欠落
3. 得意な記憶の種類
4. 初期武器
5. 必殺技
6. 友人関係
7. 誤解
8. 反転
```

この型があれば、20人まで増えても整理できる。

---

# 2. キャラの役割

役割は、ゲーム内の機能と物語上の意味を兼ねる。

例:

```txt
拾う
名前をつける
道を読む
しまう
灯す
直す
聞く
運ぶ
描く
待つ
探す
渡す
守る
ほどく
結ぶ
```

よい役割:

```txt
ゲーム内の能力に変換できる
物語にも意味がある
アイテムや武器にできる
```

悪い役割:

```txt
ただ強い
ただかわいい
ただ暗い過去がある
```

---

# 3. 感情の欠落

キャラは、何かを忘れている。

ただし記憶喪失を乱用しない。

忘れているのは、事実ではなく「自分の価値の読み方」。

例:

```txt
自分は見られていない
自分は待たれていない
自分の言葉は届かなかった
自分は置いていかれた
自分は役に立てなかった
自分は名前を呼ばれなかった
```

---

# 4. 反転

各キャラには必ず温かい反転を持たせる。

例:

```txt
見られていないと思っていた
→ 小さな癖まで覚えていた人がいた

待たれていないと思っていた
→ ずっと灯りを消さずに待っていた人がいた

届かなかったと思っていた
→ 返事は書かれていたが、渡せなかった
```

重要:

```txt
痛みだけで終わらせない
```

# 5. 初期5人

## ユイ

```txt
役割: 拾う
初期武器: 夜の鉛筆
感情の欠落: 自分が忘れた/置いていったと思っている
反転: 忘れたのではなく、守るために分けた
```

## アサ

```txt
役割: 名前をつける
武器候補: 名前のラベル
感情の欠落: 名前を呼ばれなかったと思っている
反転: 名前を忘れたくなくて、言えなかった
```

## ミチル

```txt
役割: 道を読む
武器候補: 金のコンパス
感情の欠落: 帰り道を失ったと思っている
反転: 帰る場所ではなく、帰る相手があった
```

## ナギ

```txt
役割: しまう
武器候補: 月の箱 / しおり
感情の欠落: 大事なものを閉じ込めたと思っている
反転: しまったから残せた
```

## トモリ

```txt
役割: 灯す
武器候補: ランタン
感情の欠落: 誰も待っていなかったと思っている
反転: 灯りはずっと消えていなかった
```

# 6. 20人化の枠

```txt
ユイ
アサ
ミチル
ナギ

```



# 7. キャラ性能の型

各キャラは、1つの強みと1つの弱みを持つ。

```txt
ユイ: 回収型 / 安定型
ミチル: 移動型 / 位置取り型
ナギ: 防御型 / カプセル型
トモリ: 範囲光 / 必殺技型
アサ: 強化選択 / 名前付与型
```

悪い設計:

```txt
全部強い
数値だけ違う
見た目だけ違う
```

良い設計:

```txt
同じステージでも遊び方が変わる
物語上の役割と性能が一致する
```

---

# 8. 関係性の型

キャラ同士の仲の良さは、会話ではなく小物と能力で見せる。

例:

```txt
ユイの鉛筆はアサが削った
ミチルのコンパスはトモリが直した
ナギの箱にはユイの落書きがある
トモリのランタンには全員の印がある
```

これにより、プレイヤーはこう感じる。

```txt
この子たちは本当に一緒にいたんだ
```

---

# 9. 別テーマへ転用する方法

このフォーマットはVamp Pon専用ではない。

置き換え可能。

```txt
記憶 → 夢
忘れ物 → 星
黒インク → 霧
夜 → 海
欠片 → 音
```

でも構造は同じ。

```txt
失ったと思ったもの
実は残っていた証拠
拾うことで強くなる
最後に意味が反転する
```

---

# 10. 最重要

キャラは数で増やさない。

```txt
役割があるから増える。
関係があるから残る。
反転があるから好きになる。
```
