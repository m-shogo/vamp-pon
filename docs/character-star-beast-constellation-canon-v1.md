# ヨルノシルベ Character Star-Beast Constellation Canon v1

Date: 2026-08-09
Status: **CURRENT CANON FOR STORY / PROFILE / DAILY-LIFE / COLLECTION; GAMEPLAY IMPLEMENTATION DEFERRED**

> 星獣の作品1での存在法則は `docs/night-black-ink-star-beast-canon-v1.md` と一致させる。ここはCurrent21の星座割り当て・図像・重複理由の正本。

## 1. コンセプト

キャラクターの「星座」は誕生日占いの黄道星座ではない。
その人物が好きで、価値観・記憶・関係性と共鳴する **推し星座 / 守り星座** を意味する。

星獣（せいじゅう）は、その人物の価値観と生物星座が夜で共鳴し、行動できる姿を得た **観測伴走者**。
日常パート、灯録、集合絵、プロフィール、将来のassist候補でキャラクターと行動する。

星獣は:

- 神話人物の転生ではない
- Character本人の分裂人格ではない
- 万能な説明役ではない
- 通常は小さく親しみやすい
- 夜では安定後、他の参加者も基本的に視認できる
- 現実世界へ通常の物理動物として常在しない

## 2. 固定ルール

1. International Astronomical Union (IAU) の現行88星座から選ぶ。
2. 人、道具、建物、幾何学図形ではなく、**生物・動物を表す星座だけ**を使う。
3. 原則として、無関係な人物同士で同一星座を重複させない。
4. **兄弟、親族、同じ記憶から分かれた存在、Named Object lineage、継承関係など、物語上の理由がある場合のみ重複を許可する。**
5. 重複は設定ミスではなく伏線として扱う。後で関係性を知った時に「だから同じ星座だった」と分かる構造にする。
6. 同じ星座を共有しても、星獣は同一個体ではない。同じ星座から生まれた別個体として、体格、表情、傷、装飾、性格を変える。
7. 誕生日と守り星座を一致させる必要はない。占星術の性格決めには使わない。
8. 星座の神話、命名史、航海史、図像史などの「由来の核」を拾い、キャラクターの内面へ翻案する。
9. 神話の人物そのものを前世・正体にしない。
10. 星座や星獣そのものを敵として大量に倒す構造にはしない。星獣は味方 / 観測 / 案内 / マスコット側。
11. 星獣の戦闘assistは将来機能。現時点でruntime combatへ勝手に追加しない。
12. 通常時は小さく親しみやすい。暁や黒耀化では星線、輪郭、振る舞いが変わるが、巨大召喚獣へ自動昇格しない。
13. 星獣はrouteの歪み、反復、Named Objectの強い共鳴、Character状態変化を察知できる。
14. 星獣は人間の本心の最終答え、未来、Main Mysteryの完全解を知らない。
15. Characterの人気やグッズ都合で新しい重複星座を後付けしない。

## 3. 旧プロフィール星座の扱い

`docs/character-personal-profile-canon-v1.md` の旧 `zodiac` 欄は、誕生日由来の黄道星座として作られていたため、**この正本により廃止 / superseded** とする。

誕生日は日常プロフィールとして残す。


## 5. 重複星座の意味

### ユイ × トモリ — 獅子座

Current Canon:

- トモリはユイより前の現実時代で同じ物理ランタンを修理した
- ランタンは複数の手を経て後世のユイへ届いた
- 二人のLeoは**同じ灯り / Named Object lineageへ共鳴した別個体の星獣**
- ユイ×トモリを血縁Canonにはしない

OPEN:

- 中間所有者
- exact years
- 最初のランタン製作者

星座共有そのものを「血縁の証明」に戻さない。

### リツ × コヨリ — りょうけん座

既存の兄妹関係を明示的に反映する重複。
二頭で一つの星座という図像自体を利用する。

## 6. 星獣の役割

### 日常

- 食べ物を欲しがる
- 鞄や肩に乗る
- 寝る
- Characterの癖を真似する
- 他Characterの星獣と仲良し / 苦手関係を作る

星獣同士の関係はCharacter同士の関係を完全コピーしない。
人間は喧嘩していても星獣同士は妙に近い、などのズレを日常魅力へ使える。

### 観測

星獣は:

- routeの歪み
- repetition
- Named Objectの強い共鳴
- 自分のCharacterの状態変化

に敏感。

一方で:

- 人間の本心
- 正しい選択
- 未来
- Main Mysteryの完全な真相

は知らない。

### 灯録 / Character Detail

- 推し星座
- 星獣名
- 星座線
- Theme HEX / Star Beast HEX
- 由来の短文
- Characterとの共通点
- 関係性で重複している場合は、理由をstory progressionに応じて段階開示する

### TOP / 集合絵

全員の星獣を常時並べない。
画面にいるCharacterだけ、その近くへ小さく出す。

例:

- ユイの子獅子はランタンの近くで丸くなる
- トモリの若獅子は工具袋へ顎を乗せる
- リツとコヨリの二頭は互いの尻尾を追う
- シロの山猫は開いた頁へ前足を置く
- ゲンの大熊は後ろで座り、遠景へ厚みを作る

## 7. Motion

星獣はTOP motionの良い第二候補になる。

優先:

1. ランタン炎 / halo
2. 主人公や主要Characterの小さなidle
3. 星獣の小さな仕草
4. 霧 / 星 / 紙片

星獣は常に動かさない。
数秒に一度、耳、尻尾、瞬き、あくび、紙片を追う等の短いmotionにする。

## 8. 黒耀化

星獣を単純な悪い怪物へ変えない。

- 星線が欠ける
- 体の一部が紙・黒インク・煤へほどける
- いつもの癖が過剰になる
- Characterを守ろうとして近づけなくなる

等、Character自身の「一つの方法しかない」固定を星獣側にも反映する。

星獣がCharacterを外から治すのではない。
Characterが別の選択を取り戻すと、星獣の線も戻る。

## 9. 暁

暁側では巨大化より、輪郭が明瞭になり、失われていた星が一つ戻る演出を優先する。

朝へ帰った後は通常の物理動物として常在しない。
ただし夢、絵、足跡めいた痕跡、無意識の仕草として「いたこと」が残る余地がある。

## 10. Commercial / mascot boundary

Star Beastは強いcommercial入口だが、商品都合でCanonを変更しない。

許可:

- plush / charm / embroidery / sticker
- seasonal pose
- Characterとのpair art
- Star Beast同士の日常scene
- popularity analyticsで商品量 / restockを調整

禁止:

- 人気だから新しいshared constellationを追加
- 売れた星獣だけMain Mysteryの鍵にする
- Characterと無関係なmascotへ独立させすぎる
- 全員を同じ体型 / 表情 / poseへ均す

Star Beast単独商品からもCharacter / constellation / relationへ戻れる設計にする。

## 11. Production boundary

この文書のadoptionは以下を意味しない。

```txt
star-beast canon adopted != runtime summon implemented
favorite constellation adopted != combat ability assigned
shared constellation adopted != blood relation
star-beast visual brief ready != production asset approved
merchandise direction ready != merchandise production approved
```

画像制作時は、この正本の星獣種・由来・Character適合・Theme HEXをasset briefへ引き継ぐ。
