# Go / No-Go 判定表

## 目的

Vamp Pon の制作段階ごとに、次へ進むか止めるかを判断する。

感覚だけで進めると、面白くないまま作業量だけ増える。

この資料は、各マイルストーンでの判断基準として使う。

---

# 1. Prototype 1へ進む判定

## Go条件

```txt
[ ] MVP凍結リストがある
[ ] Prototype 1の目的が明確
[ ] デザインは仮素材で進めると合意済み
[ ] 仮素材で完成度評価しない
[ ] スマホ縦持ちで確認する
[ ] 1分遊べる核だけ作る
```

## No-Go条件

```txt
[ ] まだキャラや世界観を増やしたい
[ ] デザインが決まらないと作れないと思っている
[ ] Prototype 1に武器5種を入れたい
[ ] いきなり8分MVPを作りたい
```

## 判定

Goでよい。

理由:

```txt
資料は揃っている
Prototype 1の目的も明確
デザイン保留でも検証可能
```

---

# 2. Prototype 1 → Prototype 2 判定

## Go条件

```txt
[ ] スマホで動かせる
[ ] 移動が不快ではない
[ ] 自動攻撃で敵を倒せる
[ ] 欠片を拾える
[ ] 60秒以内に初レベルアップする
[ ] もう少し武器を試したいと思える
```

## No-Go条件

```txt
[ ] 移動が不快
[ ] 敵を倒すのが気持ちよくない
[ ] 欠片回収が面倒
[ ] 1分以内に何が楽しいか分からない
[ ] スマホで重い
```

## No-Go時の対応

```txt
移動速度を調整
仮想スティック調整
敵HP/速度を調整
夜の鉛筆のCT/ダメージを調整
欠片吸引範囲を調整
```

---

# 3. Prototype 2 → Prototype 3 判定

## Go条件

```txt
[ ] 3択が読める
[ ] 3択を選ぶ楽しさがある
[ ] 武器5種の違いが分かる
[ ] パッシブの効果が体感できる
[ ] 5分遊んで退屈ではない
[ ] 次にカプセル/進化を見たいと思える
```

## No-Go条件

```txt
[ ] 武器差が分からない
[ ] 3択が読みにくい
[ ] レベルアップが多すぎてテンポが悪い
[ ] パッシブが地味すぎる
[ ] 5分が長い
```

## No-Go時の対応

```txt
カード文言を短くする
武器挙動を分かりやすく差別化
Lvアップ効果を強くする
敵密度を調整
5分版を標準にする可能性を検討
```

---

# 4. Prototype 3 → スマホ実機検証 判定

## Go条件

```txt
[ ] 8分プレイできる
[ ] 3分/5分/7分の山がある
[ ] 記憶カプセルが嬉しい
[ ] 進化が強く感じる
[ ] 必殺技を使いたくなる
[ ] リザルトで次の目標がある
[ ] 仮素材でももう一度遊びたい
```

## No-Go条件

```txt
[ ] 8分が退屈
[ ] カプセルが嬉しくない
[ ] 進化できない/分からない
[ ] 必殺技が空気
[ ] 終盤が理不尽
[ ] リザルトが弱い
```

## No-Go時の対応

```txt
8分構成を再調整
カプセル報酬を強化
進化条件ヒントを追加
必殺技チャージ短縮
終盤敵密度を調整
リザルトの次目標を明確化
```

---

# 5. スマホ実機検証 → 継続プレイ検証 判定

## Go条件

```txt
[ ] iPhoneで操作できる
[ ] Androidで操作できる
[ ] 文字が読める
[ ] 終盤でも大きく重くない
[ ] 中断復帰で事故らない
[ ] 8分遊んでも疲れすぎない
```

## No-Go条件

```txt
[ ] 仮想スティックが使いにくい
[ ] ボタンが押しにくい
[ ] 敵/欠片が見えない
[ ] fpsが大きく落ちる
[ ] 端末が熱くなりすぎる
```

## No-Go時の対応

```txt
UIを大きくする
敵数/弾数/欠片数を下げる
ダメージ数字を間引く
5分標準を検討
自動必殺技をONにする
```

---

# 6. 継続プレイ検証 → デザイン本格化 判定

## Go条件

```txt
[ ] 3回遊ぶ理由がある
[ ] 次の目標が分かる
[ ] 実績/図鑑が邪魔ではない
[ ] 永続強化が強すぎない
[ ] 仮素材でも核が面白い
```

## No-Go条件

```txt
[ ] 1回で満足する
[ ] 強化しないと遊べない
[ ] 図鑑/実績が面倒
[ ] 次に何をすればいいか分からない
```

## No-Go時の対応

```txt
次目標の文言改善
永続強化コスト調整
実績条件を軽くする
図鑑通知を控えめにする
```

---

# 7. デザイン本格化 → アプリ化 判定

## Go条件

```txt
[ ] ゲーム性の核がある
[ ] スマホ操作が成立している
[ ] デザイン方針がある
[ ] 素材ライセンスが管理できる
[ ] Web版で十分に遊べる
```

## No-Go条件

```txt
[ ] 仮素材では面白くない
[ ] スマホで重い
[ ] デザインでゲーム性を救おうとしている
[ ] 継続プレイの理由が弱い
```

## No-Go時の対応

```txt
アプリ化を急がない
Web版の体験を直す
Prototype 3/5へ戻る
```

---

# 8. 最重要No-Go

以下が出たら、制作を一度止める。

```txt
MVP前にキャラを増やしている
MVP前にステージを増やしている
仮素材の見た目で判断している
スマホ確認を後回しにしている
8分が面白くないのにデザインで解決しようとしている
```

## 原則

```txt
面白くない核は、デザインしても面白くならない。
```

まず核を直す。
