# 1. 夜

## Current Canon

**夜は、人・物・言葉・記録に残った「まだ一つに決め切れない意味」が、現実の時代を越えて重なる境界層。**

- 現実世界そのものではない。
- 単なる夢ではない。
- simulationと断定しない。
- 死後世界と断定しない。
- 現実では別時代に生きる人物同士が、夜では同席できる。
- 物・言葉・記録は現実時間の因果を守って後世へ渡り、その履歴が夜で重なる。
- 夜へ来れば真相が自動的に分かるわけではない。観測・関係・物証が必要。
- 夜は朝へ帰れる場所である。

## 夜の発生と整備を分ける

夜そのものは、一人の万能なCreatorが最初から完成systemとして設計したものにはしない。

Current direction:

- 人・物・記録に残る未完の意味が長い時間をかけて重なり、Night現象が自然発生した。
- 後世の複数人物・複数時代が、帰路・観測・記録・保管の方法を継ぎ足してきた。
- 現在のNight運用は「最初の形」と同一とは限らない。

Seriesへ残す:

- 最初にNightが発生した場所 / 年代。
- 最初にNightを観測した人物。
- 最初のmaintainer群。
- Night layerが世界でどう分布するかの完全図。

# 2. 黒インク

## Current Canon

**黒インクは、悲しみ・怒り・恐怖そのものではない。出来事や自分自身へ付けた「一つの意味だけが正しい」という固定化が、夜で形を持ったもの。**

例:

```txt
失敗した
↓
失敗したから自分には価値がない
↓
他の読み方が閉じる
↓
黒インクが濃くなる
```

重要:

- 悲しい感情 = 悪ではない。
- 忘れること = 解決ではない。
- 出来事を無かったことにしない。
- 記憶を全部返すことが常に正しいわけではない。
- 本人が別の意味も選べる余地を取り戻すことが「ほどく」。

影 / 黒インクEnemyは単純な悪意の生物ではない。
固定された意味、守るために閉じたもの、繰り返された恐怖、誰かの言葉の残響などがNightでpressureを持った形になり得る。

Current defeat verbは **「ほどく」**。

# 3. 黒耀化

`黒曜化`はlegacy alias。Current visible termは **黒耀化**。

黒耀化は人格乗っ取りではない。

```txt
本人の長所
+ 守りたいもの
+ 恐怖 / 焦り
+ 「この方法しかない」という固定
↓
黒耀化
```

成長後も元の長所を捨てない。

- ユイ: 戻す力を捨てない。ただし全部を勝手に戻さない。
- ナギ: 閉じる力を捨てない。ただし誰のためにいつ閉じるかを選ぶ。
- トモリ: 直す力を捨てない。ただし傷跡まで消さない。
- クロオリ: 預かることを捨てない。ただし永遠に閉じず本人の選択時を守る。

Rescueは「仲間が治療する」のではなく、本人が一方向以外の選択を取り戻すこと。

# 4. Gameplayとの二重意味

## 記憶片

- Gameplay: EXP / build resource。
- Story: 固定された意味から剥がれ、別の読み方を持てる小片。

## Level Up

- Gameplay: build optionが増える。
- Story: そのrunで扱える「読み方」が増える。

## Game Over

- 死亡ではない。
- 「そのbuild / その読み方では朝まで届かなかった」。

## Retry

- 正史を必ず巻き戻すliteral time-loopではない。
- Nightの未確定性を別の選択で読むplay structure。

## Dawn

- 全情報の完全保存地点ではない。
- Nightで選び直した意味が、現実の小さな行動へ定着する地点。

例:

- 名前を書く前に本人へ聞く。
- 壊れた跡を少し残して直す。
- 閉じる前に帰る人がいないか確認する。
- 手紙を今渡すか待つか選ぶ。

これがHappy Endの最小単位。

# 5. 星獣

## Current Canon

**星獣は、その人物の価値観と生物星座がNightで共鳴し、行動できる姿を得た観測伴走者。**

- zodiac占いではない。
- 神話人物の転生ではない。
- Character本人の分裂人格ではない。
- 万能な神 / 召喚獣 / 説明NPCではない。
- 小さなmascot性、個体差、癖を持ってよい。
- Nightで安定した後は、参加者同士で基本的に視認できる。
- 現実世界へ通常の物理動物として常在しない。

## 察知できる

- routeの歪み。
- repetition。
- Named Objectに残る強い共鳴。
- 自分のCharacterの状態変化。
- 他Star Beastとの距離 / 警戒 / affinity。

## 知らない

- 人間の本心の最終答え。
- 未来の確定結果。
- Main Mysteryの完全な真相。
- 誰が正しいか。
- 全Characterの過去。

Star Beastへ聞けばMysteryが解ける構造は禁止。

# 8. クロオリ — 預かる思想

Current Canon:

**クロオリは、本人が「今は返さないで」と選んだ記憶を、開く時まで預かる役割を持つ。**

- 記憶を盗む人物ではない。
- 「全部隠す」が絶対正義でもない。
- 初期は「開かないこと」を安全と見なしすぎる。
- ユイは「返すこと」を善と見なしすぎる。
- 作品1で二人とも「本人が選ぶ」へ戻る。

Visual / Object motif:

- 黒折りの封。
- memory seal。
- 開封痕が残るpaper edge。

# 9. ユイのvoluntary sealed memory

Current Canonへ採用:

**過去のユイ自身が、クロオリへ一つだけ「今は返さないで」と記憶を預けている。**

ただし「危険な秘密を封印した」設定にはしない。

内容の核:

- ユイが初めて「返すことが必ずしも優しさではない」と直面した出来事。
- ある忘れ物 / 記憶を持ち主へ返そうとした時、持ち主本人から「まだ返さないで」と頼まれた。
- 当時のユイはそれを「自分は返せなかった / 失敗した」と一つの意味へ固定した。
- その記憶を、自分が別の読み方をできる時までクロオリへ預けた。

作品1終盤の反転:

- 現在のユイはクロオリへ「返して」と迫る。
- クロオリは、過去のユイ自身の依頼を守っていた。
- それでもクロオリの「預かり続けるだけ」も正解ではない。
- 最終判断を現在のユイへ戻す。

これにより二人の対立は:

```txt
返す人 vs 隠す人
```

ではなく:

```txt
過去の自分の選択を、現在の自分がどう引き受け直すか
```

へ深くなる。

具体的な忘れ物の種類 / 持ち主identityはCharacter Mysteryとして後続設計で詰める。

# 10. 強いNamed Objectが時代を越える条件

Current Canon:

**Nightで強い痕跡を持つNamed Objectは、「感情が激しかった物」ではなく、複数の人が現実時間の中で『どう残すか』を自分で選んだ物。**

強くなる行為例:

- repairする。
- 捨てずに保管する。
- 誰かへ渡す。
- すぐ渡さず待つ。
- 名前を付け直す。
- 傷を残す。
- 元通りにしない選択をする。

重要:

- 物そのものがNight teleportして歴史を飛び越えるわけではない。
- 現実時間の物理的なhandoffは必要。
- 感情の強さだけで強lineageを決めない。
- 特殊素材だから特別、にも寄せない。

ユイのランタンが強いのは「主人公の特別な神器だから」ではなく、複数の人が修理・保管・受け渡しを選んだ履歴が重なっているから。

この法則はヨルノシルベ2の「継ぐ / 渡す / 受け取る」へ直接接続する。

# 11. Night geography

Current Canon:

**Nightは世界で一枚の無限空間でも、地域ごとに完全断絶した別世界でもない。現実の場所・物・記憶clusterに対応する局所Night layerが重なり合う。**

- 各layerには濃い場所 / route / object anchorがある。
- Named Objectや帰路がlayer同士のbridgeになり得る。
- 一つのtitleで全世界のNight参加者が集合する必要はない。
- 別地域 / 別時代のlayerを作品2・3で追加しても作品1と矛盾しない。
- layer同士の境界は完全な国境ではなく、意味 / route / object historyの重なりで決まる。

OPEN:

- layer総数。
- 接続可能距離の厳密条件。
- 同時に複数layerへ属する場所の扱い。

# 12. Star Beastの起源

Current Canon:

**Star Beastは、人間が長い歴史の中で星へ見出してきた「生物の形 / 意味」の蓄積が、Nightのmeaning layerでCharacterの価値観と共鳴して姿を得る現象。**

- 星そのものが物理的な動物ではない。
- maintainerが人工的に作ったsystem componentではない。
- IAU 88星座はproduction上のCurrent mapping authorityとして使う。
- 古い時代のCharacterが必ず現代IAU名で呼んでいた、とはしない。
- 同じ星patternへ文化 / 時代によって違う呼び方が残ってよい。

これにより、古い時代のCharacterと現代のconstellation databaseの矛盾を避ける。

Seriesへ残す:

- 最古のStar Beast観測記録。
- 文化圏ごとの旧称。
- 最初に「星獣」という呼称を使った人物。

# 13. Night maintainers

Current Canon:

**Nightを帰れる場所として整えてきたmaintainerは一人ではない。複数の時代・複数の人物が、それぞれ一部の方法を継ぎ足してきた。**

役割例:

- routeを記録した人。
- 門を安全に開閉した人。
- Named Objectの履歴を残した人。
- 記憶を預かった人。
- Night observationを分類した人。
- 星獣の挙動を記録した人。

重要:

- 秘密組織一つが世界を完全管理している構造にはしない。
- maintainerも万能ではない。
- 善意だけでなく、時代ごとに異なる判断や失敗があった。
- 後世の人が古いsystemを修理・読み替えてよい。

Seriesへ残す:

- 最古のmaintainer identity。
- maintainer同士が直接つながっていたか。
- 現行Night rulesのどこが後付けなのか。
