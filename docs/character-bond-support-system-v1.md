# ヨルノシルベ Character Bond / Support System v1

Date: 2026-07-28  
Status: **USER-DIRECTION DESIGN / NOT RUNTIME IMPLEMENTED**

## 1. 目的

戦闘、好感度、日常会、呼び方、成長を別々のシステムにしない。

プレイヤーが好きな仲間を実際に戦いへ呼び、同じ夜を越えるほど関係が深まり、その結果が

- 会話
- 呼び方
- 敬語
- 表情
- 日常イベント
- 戦闘連携
- 灯合わせ

へ返ってくる循環を作る。

このシステムの感情的なゴールは、

> 「強いから連れていく」

から

> 「この二人が好きだから一緒に連れていく」

へ変わること。

---

## 2. 基本ループ

```txt
好きな主人公 / 操作キャラを選ぶ
        ↓
仲間をSupportとして戦闘へ呼ぶ
        ↓
一緒に戦う / 助ける / 特性が噛み合う
        ↓
Bond（関係経験）が増える
        ↓
拠点・日常会・戦闘後会話が変化
        ↓
呼び方 / 敬語 / 距離感 / 弱音がキャラ固有に変化
        ↓
ペア特性 / Assist / 灯合わせが育つ
        ↓
またその二人で戦いたくなる
```

---

## 3. 仲間を呼ぶ戦闘

### 3.1 主役とSupport

戦闘では操作主体とは別に、仲間をSupportとして呼べる。

Supportは単なる自動攻撃砲台にしない。

キャラごとの性格・能力が分かる行動を持つ。

例:

- アサ: 危険方向へ先回りし、短時間突破路を作る
- ナギ: 危険な弾や敵を一時的に閉じ込める
- ミチル: 帰還線 / 回復導線 / 位置修正を助ける
- トモリ: 壊れた灯具や一時ギミックを修復する
- ハナ: 回復や保護を「食事 / 保存」の表現で支援
- カナメ: 主人公の前ではなく危険側へ立って被害を受け止める
- トキ: 敵の角度やタイミングを可視化する
- レン: 弱点や見落としを短時間だけ焦点化する

### 3.2 Support人数

**現段階で固定しない。**

最初のprototypeは1 Supportでもよい。

操作性・画面密度・性能を確認して、将来2枠以上へ増やすか判断する。

キャラ数が多いからといって最初から画面へ大量召喚しない。

---

## 4. Bondは恋愛メーターではない

Bond = 一緒に過ごした時間 / 信頼 / 理解 / 関係経験。

友情、兄妹、師弟、ライバル、親族、恋愛の全てで利用できる。

```txt
Bond Level != Romance Level
```

恋愛になるかどうかはRelationship Type側で別管理する。

兄妹や師弟のBondが最大になっても恋愛にはならない。

---

## 5. Bondが上がる行動

戦闘へ連れていくだけでも少し増えるが、ただの周回作業にはしない。

候補:

- 同じ戦闘を生還する
- Support Assistを成功させる
- 主役が危険な時にSupportが救う
- 主役側がSupport条件を満たす
- 特定のペア行動を成功させる
- 灯合わせを使う
- 戦闘後の日常イベントを見る
- 相手が苦手な状況を一緒に越える
- Story Eventで関係変化を起こす

Story gateが必要な関係は、戦闘周回だけで最終段階へ到達させない。

---

## 6. 好感度 / Bond段階

既存の `relationship-speech-evolution.md` にあるLv0〜Lv5を基準にする。

```txt
Lv0 初対面 / 警戒
Lv1 仲間
Lv2 信頼
Lv3 深い信頼
Lv4 黒耀化 / 終盤級の危機を共有
Lv5 朝 / ED後の自然な関係
```

ただし**全キャラが同じ変化をしない。**

同じLv3でも、キャラによって見え方を変える。

---

## 7. 呼び方・敬語の変化

ここがシステムの重要部分。

### ユイ型

少しずつ距離が縮む。

```txt
アサちゃん → アサ
```

ただし全員呼び捨てになるわけではない。

### アサ型

呼び名はほぼ変わらない。

代わりに、

- 命令がお願いになる
- 「先に行く」が「一緒に行く」になる
- 名前を呼ぶタイミングが増える

### ナギ型

敬語 / 呼称は残ってもよい。

距離が近くなるほど説明が短くなる。

### シノ型候補

名前を呼べるようになること自体が大イベント。

### セリカ型候補

礼儀は消えない。

仲良くなるほど、完璧な敬語から少し自然な言葉へ変わる。

### ゲン型

呼び方を変えず、昔話や失敗談を話す量が増える。

### Shadow型

初期は役割名 / 距離のある呼称でもよい。

信頼後に初めて本名を呼ぶ演出も使える。

---

## 8. キャラごとの「仲良くなった証拠」

呼び捨てだけを親密さの記号にしない。

例:

- ユイ: 自分から話しかける
- アサ: 待つ
- ナギ: 預ける
- ミチル: 自分の相談もする
- トモリ: 「貸せ」ではなく「手伝え」と言える
- セン: 相手から教わる
- リツ: コヨリに任せる
- コヨリ: 兄を助けることを遠慮しない
- ゲン: 自分の失敗を話す
- ハナ: 自分の分の食事も受け取る
- ユウビ: 返事を待つため立ち止まる
- マドカ: 見たことを言葉にする
- シロ: 分からないと口にする
- トバリ: 誰かへ「帰ってこい」と言える
- ネム: 起きている時間の約束をする
- クロオリ: 自分から一つ開いて見せる
- カナメ: 荷物を人へ預ける
- カスミ: 消さずに残す
- トキ: 正確な答えがなくても進む
- ツムギ: 自分から続きを書く
- レン: 気づいたことを言う

## 9. 戦闘で強くなる仕組み

Bondを単純な「攻撃力+10%」だけにしない。

キャラの特性が強まるようにする。

### 9.1 Personal Trait

各キャラ本人が持つ固有特性。

例:

- アサ: 先行 / 突破
- ナギ: 封印 / 保護
- ミチル: 導線 / 帰還
- トモリ: 修復 / 継続
- カナメ: 防護 / 身代わり
- レン: 弱点露出

### 9.2 Bond Trait

特定の相手と一緒の時だけ変化する特性。

同じキャラでも相手によって違う。

例:

#### ユイ × アサ

ユイが危険になるとアサが先回り。  
アサが遠くへ行きすぎるとユイの灯りが帰還方向を示す。

#### ユイ × ナギ

拾った重要記憶片が一定時間失われにくくなる。

#### ユイ × トモリ

ランタン / 灯具の一時停止や破損状態を早く復帰できる。

#### リツ × コヨリ

片方が危険な時、もう片方の星獣が短時間だけ位置を知らせる。

### 9.3 Bond成長の方向

Bondが上がると、

- Assist頻度
- Assist判断
- 固有効果
- 再使用時間
- ペア効果
- 灯合わせ

などが少しずつ変化する。

数字だけでなく、アニメーションや台詞も変える。

---

## 10. 灯合わせとの接続

Core 5には既に10ペアの灯合わせcanonがある。

例:

- ユイ × アサ — `名を呼ぶ灯`
- ユイ × ナギ — `しまえない灯`
- ユイ × ミチル — `帰り道を呼ぶ灯`
- ユイ × トモリ — `消えかけを継ぐ灯`

Bondはこれらを**いきなり解放する鍵**ではなく、関係が育った結果として自然に使えるようにする。

候補フロー:

```txt
低Bond
通常Assist
↓
中Bond
固有Pair Assist
↓
高Bond + Story Gate
灯合わせ
↓
終盤Bond
演出 / 台詞 / 特性が完成形へ
```

---

## 11. 好感度を上げるためだけの作業にしない

避けること:

- 同じ弱いStageを100周
- 好感度アイテムを大量投与するだけ
- 全員同じ台詞解放
- Bond最大 = 全員恋愛告白
- +%ステータスだけ

欲しいこと:

- 一緒に戦った記憶が残る
- 前に失敗した連携が後で成功する
- 戦闘中の呼び方が変わる
- リザルトで距離感が変わる
- 日常会で以前の戦闘を覚えている

---

## 12. 成長と戦闘を一致させる例

### アサ

序盤:
> 「遅い！ 先行く！」

成長後:
> 「ユイ、行くよ」

戦闘でも、単独突進から「主人公と速度を合わせるAssist」へ強くなる。

### カナメ

序盤:
> 自分が全部受ける。

成長後:
> 主役へ防御を任せる / 交互に守る。

能力も自己犠牲一辺倒から共同防御へ。

### レン

序盤:
> 弱点を見つけても黙っている。

成長後:
> 発見時に即座に共有し、味方全員へ短い弱点windowを作る。

人物成長がそのまま性能進化になる。

---

## 13. 星獣との接続

星獣はBondの視覚表現にも使える。

- 低Bond: 星獣同士が少し距離を取る
- 中Bond: 近くに座る
- 高Bond: 一緒に遊ぶ / 寝る
- 特別な関係: 同じ動作をする
- 血縁 / 隠し関係: 人間より先に互いを知っている反応をする

UIゲージだけでなく、**星獣の距離でも仲の深まりが分かる**とヨルノシルベらしい。

---

## 14. セーブデータ設計時の境界

実装時は、最低でも次を分離する。

```txt
Character Definition
Relationship Definition
Bond Runtime State
Story Gate State
Save DTO
```

Relationship TypeとBond値を同じ値にしない。

例:

```txt
relationshipType = sibling
bondLevel = 5
```

でも恋愛にはならない。

---

## 15. 実装を急がない部分

現時点では設計のみ。

未固定:

- Support slot数
- Bond必要値
- 1戦あたり獲得量
- Assist cooldown
- Pair Traitの具体数値
- 灯合わせ解放レベル
- Romance用の別システム有無

これらはCore 5 prototypeで触ってから決める。

---

## 16. 最終的に作りたい体験

最初のユイとアサ:

> 「遅い。先に行く」

何度も一緒に夜を越え、喧嘩し、助け合った後:

> 「ユイ、行こう」

文章ではたった数文字の違い。

しかしプレイヤーは、そこに何時間分もの関係を感じる。

**好感度は数字を上げるシステムではなく、呼び方・行動・戦い方が少しずつ変わっていく履歴にする。**
