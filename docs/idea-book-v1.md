Date: 2026-07-28  
Status: **CURRENT SHARED IDEA MEMORY — IDEAS ARE NOT AUTOMATICALLY CANON**

> この本は、ユーザーとAIがこれまで話した「面白い」「入れたい」「いつか試したい」を忘れないための本。

# 1. この本の読み方

アイディアには状態を付ける。

| Label | 意味 |
| --- | --- |
| **CANON** | 既に正本として採用済み |
| **USER DIRECTION** | ユーザーが明確に「この方向がいい」と示したもの |
| **USER IDEA** | 忘れたくない案。まだ自由に育ててよい |
| **HIGH-VALUE CANDIDATE** | 相性が非常に良い候補。Human decision前に固定しない |
| **OPEN QUESTION** | 面白いが、まだ答えを決めない方がよい問い |
| **REJECTED** | 今後の通常案としては使わない |

この本の目的は、**早くルール化することではなく、忘れず育てること。**

# 2. ゲームの中心

## USER DIRECTION — まずヴァンサバ系として面白い

ヨルノシルベの中心は戦闘。

```txt
敵をほどく
→ 記憶片を拾う
→ Level Up
→ 灯具 / 持ち物でbuildを作る
→ 進化 / 黒耀化 / Supportでrunが変わる
→ 朝まで残る
→ 次は別のbuildを試す
```

物語を読むために戦うのではない。

**戦うのが楽しいから遊んでいたら、いつの間にか人物や世界が分かっている**のが理想。

# 3. 読む人と読まない人

## USER DIRECTION

### 読まない人

- 「攻撃やSupportが強くなった」
- 「新しい灯具が出た」
- 「何か開いた、ラッキー」

だけ分かればよい。

そのまま次のrunへ行ける。

### 読む人

好きなキャラや世界ができたら:

- 日常プロフィール
- 呼び方の変化
- 星獣
- 黒耀化
- 過去
- 人物同士の秘密
- 敵の背景
- 忘れ物の意味
- 世界の観測記録
- 続編への違和感

まで読める。

### 覚えておく感覚

> **情報は多くてもいい。好きになってくれた人が、自分から読みたくなる。**

全文を読むこと、既読を付けることを戦力の条件にはしない。

# 4. クリアゲッター / 夜明け星図

## USER DIRECTION — かなり大事

カービィのクリアゲッターのような、**埋めること自体が気持ちよく、次の遊び方を教えてくれる盤面**を入れたい。

Current terminology:

```txt
灯録
└ 夜明け星図
   └ 記憶のしるし
```

### 欲しい体験

普通に遊んでいるだけで:

> 「あ、3個も灯った」

少し盤面を見ると:

> 「次は黒耀化なしでクリアしてみよう」

さらに遊ぶと:

> 「このSupport同士で何かある？」

となる。

### 条件候補

- 特定キャラで夜明け
- 特定Support
- 特定灯具 / 進化
- 黒耀化あり
- 黒耀化なし
- 特定灯合わせ
- ノーダウン
- HP条件
- 時間条件
- 特定敵
- 特殊build
- 説明されないsecret

### 一番大事なこと

クリアゲッターの報酬は**ゲームへ返る**。

- 永続強化
- 灯具
- 持ち物
- キャラ
- Support
- Pair Trait
- reroll
- 特殊進化
- stage / route
- cosmetic

その横で情報も開く。

**情報だけが報酬ではない。**

# 5. Fail-forward

## USER DIRECTION

負けても完全なゼロにはしない。

ヴァンサバ系だから、またすぐ挑戦したくなることが重要。

失敗runでも小さく残せるもの:

- 敵の観察
- 地図のヒント
- 小さい永続強化
- 忘れ物の痕跡
- Bondの痕跡
- reroll / retry comfort
- optional information

ただし:

> **わざと失敗する方が得**

にはしない。

Clearは大きく前進。
Failureでも「次はいけそう」が少し増える。

# 7. 不仲な二人も使いたくなる

## USER IDEA + HIGH-VALUE CANDIDATE

「仲良しだから強い」だけでは、対立関係を使う楽しさが減る。

面白い候補:

```txt
安定した関係
→ 失敗しにくく、確実に強い

対立 / 誤解のある関係
→ 扱いに癖があるが、強い上振れや特殊効果
```

たとえばユイとShadow側。

「返す」と「隠す」の考えが衝突しているから、普通では起きない黒インク干渉ができる。

成長後も完全な仲良しにする必要はない。

> 「考えは嫌い。でも、お前ならここで動くと思ってた」

でもいい。

数値やrandom性はまだ固定しない。

# 9. 星座 / 星獣

## USER DIRECTION

各キャラには、誕生日占いとは別に**好き / 共鳴する生物星座**がある。

その星座が小さなマスコット **星獣** になる。

### 原則

なるべく星座は被らせない。

ただし:

- 兄弟
- 親族
- 血筋
- 継承
- 同じ記憶由来
- 隠された関係

など、**被る理由が物語になる場合は同じ星座でもよい。**

### 現在の強いもの

- ユイ = 獅子座 / 子獅子
- トモリ = 獅子座 / 若獅子 → なぜ同じなのか未解決
- リツ / コヨリ = りょうけん座 → 兄妹なので二頭

星獣自身の距離や行動が、人物より先に関係性を匂わせてもよい。

# 11. みんな成長する

## USER DIRECTION

デジモンの仲間たちのように、全員にそれぞれ違う弱さ・長所・成長がある。

ただし成長は性格矯正ではない。

- ネガティブな人が明るい人になる必要はない
- 無口な人が饒舌になる必要もない

> **その人のまま、前より少しだけ誰かと生きられるようになる。**

そして人物成長をGameplayにも返したい。

例:

- 自分だけで守る → 交互に守れる
- 一人で先行 → 仲間の速度に合わせられる
- 気づくだけ → 弱点を仲間へ共有する

- 食事

- 雨
- 買い物
- 修理
- 眠れない夜
- 寝坊
- 喧嘩した次の日
- 星獣の小事件

暗い人は暗いまま輪の中にいてよい。

### 好きな案

ユイとアサが喧嘩した翌日。

二人はほとんど話さない。

でも:

- アサはユイのカップへ名前を書く
- ユイはアサの忘れ物を机へ置く

その回では仲直りしなくてもいい。

# 14. 人物関係で欲しい強度

## USER DIRECTION — ユイ × アサ

ナルトとサスケのように、**二人とも主人公級の主体性を持つ強い関係**。

コピーではない。

- 衝突
- 理解
- 相互救済
- 違うまま相手を選ぶ

恋愛にはしない方向。

## USER DIRECTION — リツ × コヨリ

エドとアルのように、兄だけが守るのではなく**互いに互いを救える兄妹**。

## USER IDEA — 年を取らない魔女 × 年を取る弟子

- 師匠は若い姿のまま
- 弟子だけ普通に年を取る
- 見た目では弟子の方がずっと年上
- 二人きりでは今でも「師匠」と呼ぶ

恋愛ではなく、時間差の師弟関係として泣けるものにしたい。

## USER IDEA — お嬢様

語尾だけではなく:

- 育ち
- 姿勢
- 礼儀
- 責任感
- 頼るのが苦手

でお嬢様らしさを作る。

# 16. 物語で泣きたい

## USER DIRECTION

CLANNADのように、**キャラとの普通の時間を好きになったあとに泣ける**要素がほしい。

Little Busters!のように、**普通の現実とは少し違う場所だから成立する別れや救い**も相性がよい。

ただし作品内容はコピーしない。

### 泣きの材料

- 呼び方
- 食事
- 同じ席
- 修理した物
- 毎日の挨拶
- 一緒に帰る
- 何でもない約束

終盤で大きな台詞を突然言うより、前から繰り返していた小さな行動を返す。

# 17. Happy End

## USER DIRECTION — 非常に重要

正史は**ハッピーエンドのみ**。

犠牲や別れに見える場面はあってよい。

ただし夜は夢 / 記憶 / 仮想空間に近いので、Permanent deathを中心にしない。

欲しい着地:

- 生きている
- 目覚める
- 帰れる
- 再会できる
- 日常へ戻れる
- 前より少し成長している

悲しいことがなかったことになる必要はない。

# 19. ヤバタニエン的に好きなところ

## USER REFERENCE / DESIGN INSPIRATION

参考にしたいのは、救いのなさではなく**伏線の置き方**。

- 最初はただの配置
- 最初はただの行動
- 最初はただの人物像
- 後から見ると意味が違う

ヨルノシルベではHappy Endを守りながら、この再解釈の気持ちよさを使う。

# 23. アイディアを追加する時

今後ユーザーが新しい案を言ったら:

```txt
まずIdea Bookへ覚える
↓
既存canonと矛盾がないか確認
↓
必要ならCandidateとして育てる
↓
ユーザーが明確に決める / 実装で必要になる
↓

```

「覚える」と「固定する」を分ける。
