# 1. Status language

- `DECIDED` — User explicit。現在はYui=荒川区。
- `CURRENT_DERIVED` — 既存Character Core / Era /文化 /物語機能から現在採用。後の矛盾監査で修正可能。
- `CANDIDATE` — 強い案だがEra / family / age確定待ち。
- `OPEN` — 敢えて未設定。

Exact home addressは設定しない。

# 4. Mobility coherence classes

事件地へ来る理由は以下から選び、Era整合するものだけ使う。

- `BORN_AND_LIVES_THERE`
- `HOUSEHOLD_MOVE`
- `SCHOOL_MOVE`
- `APPRENTICESHIP`
- `EMPLOYMENT`
- `TRANSFER`
- `MARRIAGE_OR_PARTNERSHIP`
- `CARE_OF_RELATIVE`
- `DELIVERY_OR_TRANSPORT_WORK`
- `RESEARCH_OR_ARCHIVE`
- `CRAFT_OR_PERFORMANCE`
- `MILITARY_OR_STATE_ASSIGNMENT` — historical evidence必須。便利に乱用禁止
- `EVACUATION_OR_DISPLACEMENT` — tragedy shortcut禁止、Era research必須
- `FUTURE_NETWORK_BODY_OR_AVATAR_ACCESS`

**Coincidental tourism**をmain incident参加理由のdefaultにしない。

# 5. Public reveal budget

Reality rootは作者DBの深み。

### Main routeで見せる

- 0〜2個の自然な生活差
- family / friend sceneで一瞬出るregister
- food / transport / weather感覚
- incident participation reason

### Bond / optional recordで見せる

- birthplace city / ward
- family migration
- old friend
- hometown food
- 方言を隠す理由

### Author-onlyでよい

- exact childhood street
- 具体的household income等
- Storyに不要な学校名
- complete genealogy

Target:

> **設定の80〜90%は見せなくてもCharacterの一貫性に使う。**

# 7. Cross-era lineage compatibility

Root registryはCross-Era relationと矛盾させない。

親子 / 祖先子孫pairを決める時:

1. Era gapがgenerationとして成立するか
2. family migration routeが成立するか
3. surname / place / object evidenceが一致するか
4. Normal Waking memory lossを壊さないか
5. Reality evidenceがRevealをsupportするか

をcheckする。

**出身地が違う親子も普通に成立する。**
親が移住した後に子が別地域で生まれるため。

# 8. Guard

- prefecture stereotype = personality にしない。
- famous foodを毎回食べるCharacterにしない。
- 方言を全台詞へ付けない。
- skin toneからoriginを推定しない。
- real disasterをCharacter tragedyへ自動接続しない。
- major incidentへ関与するmobility reasonを必ず持つ。
- exact locationはEra / family / occupation確定時に再監査する。
- Reality setting is depth infrastructure, not exposition quota.
