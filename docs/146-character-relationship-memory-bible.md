# Character Relationship / Memory Bible

## 目的

Vamp Pon のキャラクターを、20人規模まで増やしても破綻しないようにするための設計バイブル。

この文書は、単なるキャラクター紹介ではない。

```txt
見た目の差別化
固定武器の遊び味
戦う理由
記憶テーマ
敵との関係
キャラ同士の相関
得意不得意
追加キャラ時の被り防止
```

を一本化し、キャラを増やすたびにゲームが面白くなる状態を作る。

---

# 0. 大原則

## キャラは“性能違いのスキン”にしない

Vamp Pon のキャラクターは、以下の全部がつながっている必要がある。

```txt
その子が何を持っているか
なぜそれを持っているか
どう戦うか
何を怖がっているか
誰と相性がいいか
どの記憶に反応するか
どの敵を救えるか
```

キャラが増えるほど、ただの属性違いではなく、

```txt
この子で遊ぶと、違う記憶の読み方になる
```

と感じられることを目標にする。

---

# 1. キャラ追加時の必須ゲート

新キャラを追加する時は、必ず以下の7項目で既存キャラと差別化する。

```txt
1. 持ち物
2. 髪型
3. 頭装備
4. 光の種類
5. 戦う理由
6. 固定武器の遊び味
7. 得意不得意
```

この7項目のうち、3つ以上が既存キャラと強く被る場合は、そのキャラはまだ追加しない。

被らせる場合は、必ず物語上の意味を付ける。

例:

```txt
ユイとトモリはどちらも“灯り”に関係する。
ただし、ユイのランタンは道を照らす光。
トモリのマッチは記憶を焼き付ける火。

同じ光ではなく、役割が逆。
ユイは迷子を導く。
トモリは消えそうなものを最後に残す。
```

# 2. 戦う理由の芯

Vamp Pon の戦いは、敵を殺すための戦いではない。

```txt
黒インクに固まった記憶をほどく
忘れ物に残った意味を朝へ返す
誤解された感情を正しい持ち主へ戻す
```

ための戦い。

表のゲーム:

```txt
影を倒す
欠片を拾う
レベルアップする
朝まで生き残る
```

裏の物語:

```txt
忘れられた気持ちを、もう一度読める形に戻す
```

## ハッピーエンドの条件

ハッピーエンドは、影を全滅させることではない。

```txt
影だったものが、朝の光で小さな欠片に戻る
敵だったものを、敵ではなかったと理解できる
忘れられたものが、消滅ではなく“帰る”形で終わる
```

これを徹底する。


## 関係性の方針

恋愛ではなく、友情・家族・約束・誤解の修復を中心にする。

```txt
ユイ + アサ: 名前を呼ぶ関係
ユイ + ナギ: 無理に開けない関係
ユイ + ミチル: 帰り道を探す関係
ユイ + トモリ: 消えそうな記憶を残す関係
アサ + ミチル: 進む速度と道順で衝突する
ナギ + トモリ: 閉じることと燃やして残すことで衝突する
アサ + トモリ: 軽く見せる/強がる同士で噛み合わない
ナギ + ミチル: 観察と理屈で相性は良いが、結論が遅い
```

# 8. 相性設計

キャラ同士の関係は、仲良しだけにしない。

```txt
相性が良い
考え方が違う
同じ傷を別の方法で隠している
一緒にいると強いが、不安定になる
```

を混ぜる。

## 相性タイプ

### 1. 安定ペア

例:

```txt
ユイ + ナギ
```

意味:

```txt
ユイが拾う前に、ナギが壊れないか確認する。
```

ゲーム:

```txt
防御 + スロー
初心者向け
```

### 2. 高速ペア

例:

```txt
アサ + ミチル
```

意味:

```txt
アサは早く届けたい。
ミチルは道順を確認したい。
```

ゲーム:

```txt
移動/追尾/回収が強い
火力不足になりやすい
```

### 3. 不安定高火力ペア

例:

```txt
トモリ + アサ
```

意味:

```txt
軽く流す子と、雑に燃やす子。
どちらも本音を隠す。
```

ゲーム:

```txt
高速 + 爆発
強いが事故りやすい
```

### 4. 記憶解読ペア

例:

```txt
ユイ + ミチル
```

意味:

```txt
持ち主と帰り道がつながる。
```

ゲーム:

```txt
欠片回収/追尾/安全地帯
探索向き
```

### 5. 禁忌ペア

例:

```txt
ナギ + トモリ
```

意味:

```txt
閉じて守る子と、燃やして残す子。
救い方が真逆。
```

ゲーム:

```txt
設置 + 爆発
強力だが条件付き
```

# 9. 記憶深掘りルール

キャラの記憶は、最初から説明しない。

以下の3段階で見せる。

## Phase 1: 小物だけ見せる

```txt
名札
箱
切符
マッチ
欠片
```

プレイヤーは意味を誤解してよい。

## Phase 2: 敵の挙動で違和感を出す

```txt
敵が小物を壊さない
敵が守るように回る
敵が逆走する
敵が灯りを避ける
敵が名前に反応する
```

## Phase 3: リザルト文で反転する

```txt
消えたのではない
閉じ込めたのではない
片道ではなかった
燃やしたのではなく残した
落ちていたのではなく待っていた
```

これにより、プレイヤーは後から

```txt
あの敵、ただ悪いやつじゃなかったのか
```

と気づく。

# 11. ゲームの面白さへの接続

この設計は、ストーリー資料で終わらせない。

## 見た目に効く

```txt
キャラのシルエットが被らない
装備位置が被らない
光り方が被らない
ドット絵で見分けやすい
```

## 操作感に効く

```txt
キャラごとに強い距離が違う
レベルアップで選ぶ武器の価値が変わる
同じステージでも攻略感が変わる
```

## 育成に効く

```txt
得意を伸ばすか
不得意を補うか
相性ペアで尖らせるか
```

## 物語に効く

```txt
そのキャラでしか読めない敵の意味がある
そのキャラでしか変わらないリザルト文がある
そのキャラ同士でしか見えない会話がある
```

## 推しに効く

```txt
強いから使う
見た目が好きだから使う
話が気になるから使う
相性会話を見たいから使う
```

この4つが重なると、キャラゲーとして強くなる。

# 12. 新キャラ作成テンプレート

新キャラを作る時は、以下を埋める。

```txt
名前:
役割:
記憶テーマ:

1. 持ち物:
2. 髪型:
3. 頭装備:
4. 光の種類:
5. 戦う理由:
6. 固定武器の遊び味:
7. 得意不得意:

固定武器:
得意:
不得意:

ユイとの関係:
他キャラとの衝突:
相性が良いキャラ:
相性が悪いキャラ:

反応する敵:
敵の誤解:
本当の意味:

初回リザルトSeed:
反転リザルトSeed:
不完全リザルトSeed:

既存キャラと被る要素:
被る理由:
被らないための変更:
```

# 13. 追加禁止ルール

以下のキャラは、理由なしに追加しない。

```txt
ランタン持ち2人目
フード主人公型2人目
常時光るキャラ連発
短髪元気キャラ連発
無口水属性キャラ連発
帽子＋地図キャラ2人目
火力爆発キャラ2人目
ただの闇属性ライバル
ただの回復役
ただの魔法使い
```

追加する場合は、必ず既存キャラと反対の意味を持たせる。

---

# 14. 最重要メモ

キャラが被ること自体は悪ではない。

悪いのは、

```txt
見た目だけ似ている
性能だけ違う
話に意味がない
```

こと。

良い被りは、

```txt
同じものを別の意味で持つ
同じ傷を別の方法で隠す
同じ敵を別の角度から救う
```

こと。

この設計を守ると、20キャラに増えても、

```txt
誰で遊ぶか
誰の話を読むか
誰と組ませるか
どの敵の見え方が変わるか
```

が全部ゲームの面白さになる。
